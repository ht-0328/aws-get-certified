1. 受験する資格の選び方

AWS 認定は難易度別に4つのレベルに分かれています。AWS の学習を始めたばかりであれば、基礎レベルの「クラウドプラクティショナー」から受験するのが一般的です。

専門知識（Specialty）

セキュリティ、機械学習など特定分野の専門知識

プロフェッショナル（Professional）

大規模で複雑なシステムの設計・運用

アソシエイト（Associate） ← 2つ目の目標

ソリューションアーキテクト アソシエイト（SAA）：AWS 上でのシステム設計

基礎（Foundational） ← 最初の目標

クラウドプラクティショナー（CLF）：クラウドと AWS の基礎知識

下から順に難易度が上がります。本サイトは CLF の範囲を中心に、SAA で必要な内容も含めています。
各章の CLFSAA は、対象となる試験を示します。

4. 4週間の学習計画（CLF の例）

学習を始める前に、目的（どの試験か）、期限（試験日まで何週間か）、現状（用語が分かる段階か、使い分けができる段階か）の3点を確認してください。試験日まで2週間程度しかない場合は、模擬試験と弱点分野の想起練習を優先します。

1日1時間程度を想定した計画です。新しい章の学習と既習章の復習を同じ週の中に組み込み、間隔反復を実現しています。

週新しく学習する範囲復習
1週目学習方法 → 第1章 → 第2章 → 第3章各章の1日後・3日後の想起練習。毎日、復習カードを10分。
2週目第4章 → 第5章 → 第6章1週目の章の7日後の復習。毎日、復習カード。
3週目第7章 → 第8章 → 第9章2週目の章の7日後の復習と、1週目の章の14日後の復習。
4週目公式の練習問題・模擬試験誤答した問題に関連する章を読み直し、想起練習を行う。
🔬根拠：模擬試験も想起練習である
問題を解くことは、それ自体が効果の高い復習になります（テスト効果）。AWS Skill Builder の公式練習問題（CLF-C02、20問・無料）は本番に近い形式のため、必ず取り組んでください。誤答した問題は、正答の根拠を自分の言葉で説明できるまで復習します。

5. 解答の進め方

問題文のキーワードとサービスを対応づける

AWS 認定試験では、問題文に含まれる要件を示すキーワードによって正答が絞り込めることが多くあります。

問題文の要件正答の候補
「誰が・いつ・どの API を呼び出したかを記録したい」CloudTrail
「サーバーを管理せずに、イベントを契機にコードを実行したい」Lambda
「世界中の利用者に低遅延でコンテンツを配信したい」CloudFront
「ほとんどアクセスしないデータを、最も低コストで長期保管したい」S3 Glacier Deep Archive
「中断を許容できる処理を、最も低コストで実行したい」スポットインスタンス
「AWS のセキュリティ・コンプライアンスに関する監査レポートを入手したい」AWS Artifact

各章の 🎯 試験での問われ方 に、同様の対応を分野ごとにまとめています。

消去法を用いる

  • まず明らかに誤りの選択肢を除外する（存在しないサービス、役割がまったく異なるサービスなど）。
  • 「最もコスト効率が高い」「運用上の負担が最も少ない」など、問題文の制約条件を正確に読み取る。
  • 複数選択問題（「2つ選択してください」など）は、指定された数だけ選ぶ。1つしか選ばないと、それが正しくても不正解になる。

公式練習問題の結果の使い方

結果画面の「問題の詳細」には、問題ごとの正誤・選んだ答え・各選択肢の根拠が出ます。次の順に使ってください。

  1. 選ぶ数を間違えた問題を先に除く。「2つ選択」で1つしか選んでいない不正解は、知識ではなく読み方の問題。
  2. 残りの不正解は、問題文のどの言葉で答えが決まるかを書き出す。例：「既存のインターネット接続を使う」→ VPN、「サーバーを EC2 へ移行」→ MGN。
  3. 正解でも「わからない」「根拠のある推測」で答えた問題は、不正解と同じ扱いで復習する。
  4. 1問あたり30秒未満で答えていたら速すぎる。本番は65問90分（1問あたり約80秒）なので、問題文を最後まで読む。
  5. 結果ページは保存しておき、2回目以降と比べる。

練習問題で落としやすい問いと、その答え・該当する章です。

問い答え章
プログラムによるアクセスに必要な認証情報（2つ）アクセスキー ID とシークレットアクセスキー第1章・第2章
RDS を複数の AZ に置くのは Well-Architected のどの柱か信頼性第7章
データベースが動いているサーバーをそのまま EC2 へ移すMGN（DMS はデータの移行）第8章
テキストを音声で読み上げるPolly第8章
既存のインターネット接続で暗号化した接続を作るSite-to-Site VPN第6章
責任共有モデルで利用者の責任（2つ）IAM の最小権限、セキュリティグループの設定第2章
部門ごとのアカウントの支払いをまとめ、統制（ガバナンス）を1か所にOrganizations第9章
S3 の静的サイトを低遅延・高速に配信CloudFront（Route 53 ではない）第6章
電話のテクニカルサポートがある最下位のプランビジネス第9章
無制限アクセスを許可しているセキュリティグループを特定Trusted Advisor第7章・第9章
S3 の機密データを自動で検出・分類Macie（Secrets Manager ではない）第2章
世界中に顧客がいる企業の利点（2つ）CloudFront のエッジロケーション、複数リージョンへの配置（ELB はリージョンをまたげない）第1章
S3 の特性（2つ）オブジェクトストレージ、高い耐久性第4章

選んだ答えを検証する

1つの選択肢を選んだら、「この答えが誤りだとすればどこか」を確認し、他の選択肢と可用性・コスト・性能・運用負荷・セキュリティの観点で比較してください。詳しくは学習方法の「試験問題で判断を誤らないための6つの視点」を参照してください。

6. 問題文によく出る言葉

問題文や選択肢には、AWS のサービス名以外にも IT 業界のカタカナ語が多く出ます。意味が分からないと問題文が読めないので、やさしい日本語で言い換えます。用語集でも検索できます。

問題文の型

言葉やさしく言うと
ソリューション
Solution		解決策。どの方法やサービスの組み合わせで実現するか。
「要件を満たすソリューションはどれか」＝どうやって実現するか
コンポーネント
Component		部品。システムを作っている個々のサーバーやプログラム。
「コンポーネントを疎結合にする」＝部品どうしの依存を弱める
ワークロード
Workload		動かしている仕事。システムやアプリのまとまり。
「ワークロードを AWS に移行」＝そのシステムを移す
アーキテクチャ
Architecture		構成。どのサービスをどうつないで作るか。
「アーキテクチャを設計する」＝構成を決める
インフラストラクチャ（インフラ）
Infrastructure		土台。サーバー・ネットワーク・保存場所などの設備。
「インフラを管理したくない」＝設備の面倒を見たくない

マネージド
