第2章 セキュリティとIAM

AWS の試験でいちばん配点が大きい分野の一つがセキュリティです。「だれが・何を守るのか」「だれに・何をさせてよいのか」を、たとえ話と図でおさえましょう。

🗺️この章の地図
  1. 責任共有モデル（AWS とお客さんの役割分担）
  2. IAM（だれに、何をさせてよいか）
  3. たくさんのアカウントをまとめる（Organizations・IAM Identity Center）
  4. カギと秘密を守る（KMS・CloudHSM・Secrets Manager・ACM）
  5. 攻撃から守る（Shield・WAF）
  6. 見張りと調査（GuardDuty・Inspector・Macie・Security Hub・Detective）
  7. その他（Artifact・Cognito）

1. 責任共有モデル —— だれが何を守る？

クラウドでは、セキュリティを AWS とお客さん（あなた）で分担します。これを責任共有モデルといいます。

🏢たとえ話：マンションを借りる

AWS は大家さん。建物の頑丈さ、オートロック、エレベーターの点検（＝データセンター・機械・ネットワークの土台）に責任をもちます。

あなたは住人。自分の部屋のカギをかける、だれに合カギを渡すか決める、部屋の中の大事なもの（＝データ・設定・パスワード）を守るのはあなたの責任です。

🔑覚え方：「クラウドの」と「クラウドの中」

AWS ＝ Security OF the Cloud（クラウドそのもののセキュリティ）
お客さん ＝ Security IN the Cloud（クラウドの中に置いたもののセキュリティ）

「AWS は箱、あなたは中身」と覚えましょう。

2. IAM —— だれに、何をさせてよいか

IAMアイアム／Identity and Access Management
AWS をだれが使えて、何をしてよいかを決めるサービス。無料。リージョンに関係なく使えるグローバルサービス。
🏨たとえ話：ホテルのカードキー
  • ユーザー＝ 名札をつけた1人のスタッフ。
  • グループ＝「清掃係」「フロント係」などの係。係ごとにカードキーの権限を決めれば、人が増えても楽。
  • ポリシー＝「この係は3階の部屋に入ってよい」という許可のルール表。
  • ロール＝一時的に貸し出す腕章。腕章をつけている間だけ、その権限が使える。人だけでなく、EC2 などの AWS サービスにも貸せる。

部品なに？ポイント
ルートユーザーアカウントを作ったときの最強のユーザー（メールアドレスでログイン）ふだんは使わない。MFA を設定してしまっておく。
IAM ユーザー1人（または1つのプログラム）用のログイン情報1人1ユーザー。使い回さない。
IAM グループユーザーのまとまりグループにポリシーを付けると管理が楽。グループの中にグループは入れられない。
IAM ポリシー許可・拒否のルール（JSON で書く）「明示的な拒否（Deny）」がいちばん強い。何も書いていなければ拒否。
IAM ロール一時的に借りる権限EC2・Lambda などのサービスや、別アカウントの人に貸す。期限つきの認証情報が自動で発行される。

ルートユーザーでしかできないこと

ルートユーザーは強すぎるので、ふだんは IAM ユーザー（や IAM Identity Center）で作業します。ただし、次のようなアカウントそのものに関わる操作はルートユーザーでしかできません。

  • アカウントの解約（閉鎖）
  • サポートプランの変更
  • ルートユーザーのメールアドレスなど、アカウント設定の変更

セキュリティの基本ルール

🔑覚え方：IAM の3原則「最小・二重・使わない」
  1. 最小権限の原則：仕事に必要な分だけの権限をあたえる。
    （ホテルの清掃係に、金庫のカギまで渡さない）
  2. 二重のカギ＝ MFA：パスワード＋スマホのアプリなど、2つで本人確認する。
    MFA（多要素認証）＝「知っているもの（パスワード）」と「持っているもの（スマホ）」など、ちがう種類の証拠を組み合わせて本人確認すること。
  3. ルートユーザーは使わない：アクセスキーも作らない。

⚠️ひっかけ注意
  • 「EC2 から S3 にアクセスさせたい。アクセスキーを EC2 に保存する」→ ×。正解は IAM ロールを EC2 に付ける。
  • 「管理者全員でルートユーザーを共有する」→ ×。1人1つの IAM ユーザー（または Identity Center のユーザー）を作る。
  • IAM はリージョンごとではなく、グローバル。

3. たくさんのアカウントをまとめる

会社が大きくなると、「開発用」「本番用」「経理用」など、AWS アカウントをいくつも持つのがふつうです。それをまとめて管理するサービスがあります。

AWS Organizationsオーガニゼーションズ
複数のアカウントを1つの会社（組織）としてまとめる。請求を1つにまとめる一括請求ができ、SCP でアカウントごとに「やってはいけないこと」を決められる。
IAM Identity Centerアイデンティティセンター（旧 AWS SSO）
1回ログインするだけで、複数のアカウントやアプリに入れるしくみ（シングルサインオン）。会社の社員名簿（Microsoft Entra ID など）ともつなげられる。
🏫たとえ話：学校と校則

Organizations は「学校」、各アカウントは「クラス」。SCP（サービスコントロールポリシー）は校則です。担任の先生（IAM）が「スマホOK」と言っても、校則で「スマホ禁止」なら使えません。SCP は「ここまでしかできない」という上限を決めるだけで、権限をあたえるものではありません。

🎯試験に出るポイント
  • 「複数アカウントの請求をまとめたい／まとめ割引を受けたい」→ Organizations の一括請求
  • 「特定のアカウントで、特定のサービスやリージョンを使えなくしたい」→ SCP
  • 「社員が1回のログインで複数アカウントに入れるようにしたい」→ IAM Identity Center

4. カギと秘密を守る

データを暗号化するには「カギ」が必要です。そのカギや、パスワードなどの「秘密」を安全にしまうサービスです。

サービスたとえなにをする？
KMS
Key Management Service		銀行の貸し金庫（AWS が管理）暗号化のカギを作って管理する。S3・EBS・RDS などとかんたんに連携。だれがカギを使ったかは CloudTrail に記録される。
CloudHSM自分専用の金庫を丸ごと借りるカギをしまう専用の機械（HSM）を自分だけで使う。カギの管理は完全に自分。きびしいルールがある会社向け。
Secrets Managerパスワード帳＋自動で書きかえデータベースのパスワードなどの秘密情報を保管。定期的に自動で変更（ローテーション）できるのが特長。
ACM
Certificate Manager		お店の営業許可証サイトを https（鍵マーク）にするための SSL/TLS 証明書を発行・自動更新。ELB や CloudFront で使う公開証明書は無料。
🔑覚え方：カギ4兄弟

KMS ＝ Key（カギ）／ CloudHSM ＝ Hardware（専用機械）／ Secrets ＝ 秘密（パスワード）／ ACM ＝ Certificate（証明書）

名前の中に答えが書いてある！ 英単語の意味で覚えると忘れにくいです。

⚠️ひっかけ注意

「パスワードを自動でローテーションしたい」→ Secrets Manager。似たサービスの Systems Manager の Parameter Store も値を保存できますが、自動ローテーションの機能は Secrets Manager の強みです。
「専用のハードウェア」「自分だけがカギを管理」→ CloudHSM。

5. 攻撃から守る —— Shield と WAF

インターネットに公開したサイトは、いろいろな攻撃を受けます。代表的なのが DDoS 攻撃です。

🏯たとえ話：お城の守り

Shield（シールド）＝ お城の大きな盾・城壁。大軍がおしよせて門をふさぐ（DDoS）のを防ぐ。

WAF（ワフ）＝ 城門の門番。1人ずつ荷物を調べて、あやしい荷物（悪意のあるリクエスト）を持った人を入れない。

攻撃者・利用者
→
Shield大量アクセスを防ぐ
→
WAF中身をチェック
→
CloudFront/ ALB など
→
あなたのサイト
Shield が「量」の攻撃を、WAF が「中身」の攻撃を止めます。
サービス守るもの料金・特長
Shield Standardよくある DDoS 攻撃無料・自動。すべてのお客さんに最初から付いている。
Shield Advanced大規模・高度な DDoS 攻撃有料。24時間365日の専門チーム（SRT）のサポート、攻撃で増えた料金の補償など。
WAFSQL インジェクション・XSS など、Web の中身をねらう攻撃ルールを書いて、特定の IP アドレスや国、あやしいリクエストをブロック。CloudFront・ALB・API Gateway などに付ける。

6. 見張りと調査 —— 「見張り系」サービス

名前が似ていてまちがえやすいゾーンです。「だれが・何を見ているか」でグループ分けして覚えましょう。

🕵️たとえ話：警備会社のチーム
  • GuardDuty（ガードデューティ）＝ 警備員（ガードマン）。防犯カメラ（ログ）を24時間見て、あやしい動きを見つけたら知らせる。
  • Inspector（インスペクター）＝ 建物の検査官。EC2 やコンテナに弱点（脆弱性）がないか検査する。
  • Macie（メイシー）＝ 金庫の中身係。S3 の中に、クレジットカード番号などの個人情報がまぎれていないか探す。
  • Detective（ディテクティブ）＝ 探偵。事件が起きたあとに、原因や流れを調べる。
  • Security Hub（セキュリティハブ）＝ 警備本部。みんなの報告を1か所に集めて、全体の点数を出す。

🔑覚え方：「ガ・イ・メが見つけて、ハブに集めて、探偵が調べる」

GuardDuty（ガードマン）・Inspector（インスペクター＝検査官）・Macie（メイシー＝S3の中身）→ Security Hub → Detective（探偵）

Macie は「Macie ＝ My 個人情報を S3 で探す」と覚えてもOK。

⚠️ひっかけ注意

GuardDuty は「見つける」だけで、攻撃を止めるわけではありません。止めるのは WAF やセキュリティグループなど。また、「だれがどの操作をしたかの記録」は CloudTrail（第7章）で、GuardDuty はその記録を分析する側です。

7. その他のセキュリティサービス

AWS Artifactアーティファクト
AWS が受けた第三者の監査レポート（ISO・SOC・PCI DSS など）をダウンロードできるポータル。「AWS がルールを守っている証明書がほしい」→ Artifact。
監査（かんさ）＝外部の専門家が、決まりを守っているかチェックすること。
Amazon Cognitoコグニート
あなたが作るアプリの利用者のログイン機能（会員登録・サインイン・Google ログインなど）をかんたんに作れる。IAM は「AWS を操作する人」、Cognito は「アプリを使うお客さん」のためのもの。
🎯試験に出るポイント（まとめ）
  • 「コンプライアンスのレポートを入手」→ Artifact
  • 「モバイルアプリに会員登録・ログイン機能を追加」→ Cognito
  • 「DDoS 対策を無料で」→ Shield Standard／「専門チームの支援がほしい」→ Shield Advanced
  • 「SQL インジェクションを防ぐ」→ WAF
  • 「暗号化キーを管理」→ KMS／「専用ハードウェアで」→ CloudHSM

責任共有モデルで、AWS とお客さんの担当をひと言でいうと？
AWS は「クラウドの（OF）」セキュリティ＝箱。お客さんは「クラウドの中の（IN）」セキュリティ＝中身（データ・設定・権限）。
EC2 と RDS で、OS やデータベースソフトのパッチを当てるのはそれぞれだれ？
EC2 はお客さん。RDS は AWS（マネージドサービスなので）。
IAM のユーザー・グループ・ポリシー・ロールを、ホテルでたとえると？
ユーザー＝スタッフ1人、グループ＝係、ポリシー＝許可のルール表、ロール＝一時的に貸し出す腕章。
EC2 から S3 にアクセスさせる正しい方法は？
EC2 に IAM ロールを付ける（アクセスキーを保存しない）。
IAM の3原則は？
最小権限の原則／MFA を使う／ルートユーザーはふだん使わない（最小・二重・使わない）。
ルートユーザーでしかできない操作の例を2つ。
アカウントの解約、サポートプランの変更（ほか、ルートのメールアドレスなどアカウント設定の変更）。
SCP は権限を「あたえる」もの？
あたえない。Organizations のアカウントで「ここまでしかできない」という上限（校則）を決めるだけ。
Shield と WAF のちがいは？
Shield は DDoS（大量アクセス）から守る盾。Standard は無料・自動、Advanced は有料で専門チーム付き。WAF は SQL インジェクションなど Web リクエストの中身をチェックする門番。
見張り系5つ（GuardDuty・Inspector・Macie・Security Hub・Detective）の役割は？
GuardDuty＝あやしい動きの検出、Inspector＝脆弱性の検査、Macie＝S3 の個人情報を発見、Security Hub＝結果を一元化、Detective＝原因の調査。
パスワードを自動でローテーションしたいときのサービスは？ 証明書の場合は？
Secrets Manager。証明書は ACM（自動更新）。
AWS の監査レポートを入手するサービスは？ アプリのお客さんのログイン機能は？
AWS Artifact。ログイン機能は Amazon Cognito。
