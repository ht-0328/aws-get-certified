第3章 コンピューティング（サーバー）

「コンピューティング」とは、計算する力＝プログラムを動かす力のこと。AWS でサーバーを借りる方法は1つではありません。「どこまで自分で面倒をみるか」で、使うサービスが変わります。

🗺️この章の地図
  1. EC2 —— 仮想サーバーを借りる（AMI・インスタンスタイプ）
  2. EC2 の買い方（オンデマンド・RI・Savings Plans・スポット・専有）
  3. Auto Scaling と ELB —— 増やす・減らす・ふり分ける
  4. Lambda —— サーバーを意識しない（サーバーレス）
  5. コンテナ（ECS・EKS・Fargate・ECR）
  6. その他（Lightsail・Elastic Beanstalk・Batch・Outposts）
🔑先に全体像：面倒をみる量で並べる

EC2（全部自分）→ コンテナ（箱づめして運ぶ）→ Lambda（コードだけ）

右に行くほど「AWS におまかせ」が増え、自分の手間は減ります。第2章の責任共有モデルとつながっています。

1. EC2 —— 仮想サーバーを借りる

Amazon EC2イーシーツー／Elastic Compute Cloud
数分で使える仮想サーバーを借りるサービス。OS から上は自分で自由に設定できる（＝IaaS）。借りた1台1台をインスタンスと呼ぶ。
🚗たとえ話：レンタカー

EC2 はレンタカーです。車種（インスタンスタイプ）を選び、カーナビやシートの設定（AMI）を選んで借ります。運転（OS の更新やソフトの管理）は自分でします。

AMI —— サーバーの「ひな形」

AMI は、OS や入れておきたいソフトをセットにしたサーバーのひな形です。自分で作った AMI から同じサーバーを何台でもコピーできます。

インスタンスタイプ —— 車種を選ぶ

「CPU が強い」「メモリが多い」など、用途に合わせて選びます。名前は m7g.large のように「ファミリー・世代・追加の特徴・サイズ」でできています。

ファミリー得意なこと代表的な文字たとえ
汎用バランス型。Web サーバーなどM・Tふつうの乗用車
コンピューティング最適化CPU をたくさん使う計算C（Compute）スポーツカー
メモリ最適化大量のデータをメモリに置いて処理R（RAM）・X大きな作業机つきのワゴン車
高速コンピューティングAI の学習・画像処理（GPU などを使う）P・G・Inf・Trn特殊車両
ストレージ最適化ディスクの読み書きが大量I・Dトラック

ストレージ（ディスク）は2種類

EC2 につなぐディスクは、ふつう EBS（第4章でくわしく）を使います。インスタンスを止めてもデータが残るネットワーク上のディスクです。一方、インスタンスストアはサーバーに直接ついた高速ディスクですが、インスタンスを停止するとデータが消えます（一時的な置き場所向け）。

2. EC2 の買い方（購入オプション）

同じ EC2 でも、買い方で料金が大きく変わります。試験ではほぼ確実に出ます。

🏨たとえ話：ホテルの泊まり方
  • オンデマンド＝ 当日予約の素泊まり。いつでも泊まれて、いつでも帰れる。でも定価。
  • リザーブドインスタンス（RI）＝ 1年・3年の長期契約の部屋。部屋（インスタンスタイプ）は固定だけど、大きく割引。
  • Savings Plans＝ 「1時間あたりこれだけ使います」という金額の約束。部屋は変えてもいいので、RI より自由。
  • スポットインスタンス＝ 空き部屋の激安セール。ただし、ほかのお客さんが来たら2分前の予告で追い出される。
  • Dedicated Hosts＝ 建物（物理サーバー）を丸ごと貸し切り。
買い方割引向いている使い方
オンデマンドなし（定価）
秒・時間単位で払う		短期間・予測できない・中断されたら困る仕事。お試し。
リザーブドインスタンス最大 約72%1年か3年、ずっと動かすことがわかっている仕事（例：いつも動いているデータベース）。
Savings Plans最大 約72%1年か3年の利用金額を約束。Compute Savings Plans なら EC2 のタイプやリージョン、Fargate・Lambda にも使える柔軟さが魅力。
スポットインスタンス最大 約90%途中で止まってもやり直せる仕事（データの一括処理・テストなど）。
Dedicated Hostsなし（高め）物理サーバーを専有。今持っているソフトのライセンス（サーバー単位の契約）を持ちこみたいとき。法律上、他社と共有できないとき。
Dedicated Instancesなし（高め）自分専用のハードウェアで動かす（ただし物理サーバーの細かい管理はできない）。
キャパシティ予約なし特定の AZ で、必要なときに確実に起動できる枠をおさえておく。
🔑覚え方：「いつ止まってもいい→スポット、ずっと動く→RI/SP、よくわからない→オンデマンド」

スポット＝「スぐポイっと追い出される、でもトても安い」

Dedicated＝「デーンと建物ごと」→ ライセンス持ちこみ・規制対応。

⚠️ひっかけ注意
  • 「中断できない重要な処理をいちばん安く」→ スポットは×（中断されるかも）。期間が長ければ RI か Savings Plans、短ければオンデマンド。
  • 「ライセンスを持ちこみたい（BYOL）」→ Dedicated Hosts。Dedicated Instances とまちがえないこと。
    BYOL＝Bring Your Own License。自分が持っているソフトの使用権をクラウドで使うこと。

3. Auto Scaling と ELB —— 増やす・減らす・ふり分ける

🍜たとえ話：人気ラーメン店

ELB は入口の案内係。並んでいるお客さんを、空いている店員（サーバー）へ順番にふり分けます。調子の悪い店員（こわれたサーバー）には案内しません。

Auto Scaling は店長。行列が長くなったらアルバイトを自動で増やし、ひまになったら帰す。いつでも最低何人いるか・最大何人までか、も決めておけます。

1つの AZ が止まっても、ELB はもう一方の AZ の EC2 へ案内し、Auto Scaling が足りない台数を自動で補います。これで高可用性と伸縮性の両方が手に入ります。
Amazon EC2 Auto Scalingオートスケーリング
EC2 の台数を自動で増減。こわれた EC2 を自動で入れかえる役目もある。
増やし方：ターゲット追跡（例：CPU 使用率を50%に保つ）／スケジュール（例：毎朝9時に増やす）／予測（過去のパターンから前もって増やす）など。
Elastic Load Balancing（ELB）ロードバランサー
届いた通信を複数のサーバーにふり分ける（負荷分散）。ヘルスチェックで、こわれたサーバーには送らない。

ELB の3種類

種類得意なことキーワード

🎯試験に出るポイント
  • 「アクセスの増減に合わせて自動で台数を変えたい」→ Auto Scaling
  • 「複数の EC2 に通信を分散し、1台がこわれても止まらないように」→ ELB（＋複数 AZ）
  • 「URL のパスで送り先を変えたい」→ ALB／「超高性能・固定 IP」→ NLB

4. Lambda —— サーバーを意識しない

AWS Lambdaラムダ
コードを置いておくだけで、何か起きたとき（イベント）に自動で動く。サーバーの準備・管理はいらない（＝サーバーレス）。動いた回数と時間（ミリ秒単位）だけお金がかかる。
💡たとえ話：人感センサーのライト

EC2 は「つけっぱなしの電気」。だれもいなくても電気代がかかります。Lambda は「人が来たときだけ光る人感センサーライト」。来なければ0円です。

⚠️ひっかけ注意

Lambda は 1回の実行が最大15分まで。「何時間もかかる処理」には向きません（EC2・Batch・Fargate などを使う）。

5. コンテナ —— 荷物を箱づめして運ぶ

コンテナは、アプリと必要な部品を1つの箱にまとめたものです。

🚢たとえ話：貨物コンテナ

港の貨物コンテナは、中身が何でも同じ形の箱なので、どの船・トラックにも積めます。IT のコンテナも同じで、「自分のパソコンでは動いたのに、サーバーでは動かない」が起きにくくなります。

  • ECR＝ コンテナの倉庫（箱の設計図＝イメージを保管）
  • ECS / EKS＝ どの船に何個積むかを決める港の管理人（オーケストレーション）
  • Fargate＝ 船ごと AWS が用意してくれるサービス。自分は箱を渡すだけ

6. その他のコンピューティングサービス

Amazon Lightsailライトセイル
月額固定のかんたんサーバー。サーバー・ディスク・ネットワークがセット。「AWS にくわしくない人が、小さなサイトや WordPress をかんたんに」→ Lightsail。
AWS Elastic Beanstalkビーンストーク
コードをアップロードするだけで、EC2・ELB・Auto Scaling などを自動で組み立ててくれる（PaaS）。「インフラを気にせず、Web アプリをすばやく公開」→ Beanstalk。
AWS Batchバッチ
大量のバッチ処理を自動で計画・実行。必要な台数のサーバーを用意し、終わったら片付ける（スポットとも相性がよい）。
AWS Outpostsアウトポスト
AWS のサーバー機械を自社のデータセンターに置いて、AWS と同じように使う。「データを社内に置いたまま AWS のサービスを使いたい」→ Outposts（ハイブリッド構成）。
🎯試験に出るポイント（まとめ）
  • 「サーバーの管理をしたくない」「イベントで動かす」→ Lambda
  • 「コンテナを動かしたいがサーバー管理はしたくない」→ Fargate
  • 「Kubernetes」→ EKS
  • 「コードを上げるだけで Web アプリ環境を自動構築」→ Elastic Beanstalk
  • 「月額固定・かんたん」→ Lightsail
  • 「自社のデータセンターで AWS を使う」→ Outposts

EC2・コンテナ・Lambda を「自分の手間」の多い順に並べると？
EC2（全部自分）＞ コンテナ ＞ Lambda（コードだけ）。
AMI とは？
OS やソフトをセットにした、サーバーのひな形。同じサーバーを何台でも起動できる。
インスタンスタイプの5つのファミリーは？
汎用（M・T）、コンピューティング最適化（C）、メモリ最適化（R・X）、高速コンピューティング（P・G など）、ストレージ最適化（I・D）。
EC2 の購入オプションと、それぞれ向いている使い方は？
オンデマンド＝短期・予測不能・中断不可。RI／Savings Plans＝1〜3年ずっと使う（最大約72%割引、SP は柔軟）。スポット＝中断してもよい処理（最大約90%割引）。Dedicated Hosts＝ライセンス持ちこみ・規制対応。
スポットインスタンスの注意点は？
AWS の都合で2分前の通知で中断されることがある。中断できない処理には使わない。
Auto Scaling と ELB の役割を、ラーメン店でたとえると？
ELB＝入口の案内係（空いている店員にふり分け、調子の悪い店員には案内しない）。Auto Scaling＝店長（混んだら人を増やし、ひまなら帰す）。
ALB・NLB・GWLB の使い分けは？
ALB＝HTTP の中身（URL のパスなど）でふり分け（レイヤー7）。NLB＝TCP/UDP を超高速・固定 IP（レイヤー4）。GWLB＝他社製セキュリティ機器へ通す。
Lambda の特徴と、向かない処理は？
サーバー管理不要、イベントで動き、回数と時間だけ課金。1回最大15分なので長時間の処理には向かない。
ECS・EKS・Fargate・ECR のちがいは？
ECS＝AWS 独自のコンテナ管理、EKS＝Kubernetes、Fargate＝コンテナ用サーバーレス実行環境、ECR＝コンテナイメージの保管場所。
Lightsail・Elastic Beanstalk・Outposts はそれぞれどんなとき？
Lightsail＝月額固定のかんたんサーバー。Beanstalk＝コードを上げるだけで環境を自動構築。Outposts＝自社のデータセンターで AWS を使う。
