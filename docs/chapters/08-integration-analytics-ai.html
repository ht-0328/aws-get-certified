1. つなぐ —— 疎結合とメッセージのサービス

システムはいくつもの部品（サーバーやプログラム）でできています。部品どうしが直接、がっちりつながっている状態を密結合、あいだにクッションをはさんでゆるくつながっている状態を疎結合といいます。AWS は疎結合にしましょうとすすめています。

🍜たとえ話：ラーメン屋の注文

密結合＝店員が注文を聞いて、料理人に手渡しするまでその場で待つ。料理人が忙しいと、店員もお客さんも止まってしまう。

疎結合＝店員は注文を伝票ホルダー（キュー）にさして、すぐ次のお客さんのところへ。料理人は自分のペースで伝票を取って作る。料理人が1人休んでも、伝票は消えずに待っている。

密結合 vs 疎結合（SQS をあいだにはさむ）
✕ 密結合：注文係が止まると、全部止まる
注文を受けるWebサーバー
→直接わたす
処理する処理サーバー
（故障中…）
◯ 疎結合：キューが注文をためておく
注文を受けるWebサーバー
→入れる
Amazon SQS伝票ホルダー
（キュー）
→取りに行く
処理する自分のペースで
処理サーバーが止まっても、注文（メッセージ）は SQS の中で待っていてくれる。
アクセスが急に増えても、キューにたまるだけで受付は止まらない。
📝ことばメモ
メッセージ
部品どうしでやりとりする「伝言」。注文内容や「処理してね」というお願いなど。
キュー
メッセージを順番待ちの列にためておく場所。英語で「行列」の意味。
プッシュ
相手に向かって送りつけるやり方。SNS はこれ。
ポーリング
受け取る側が「何か来てる？」と取りに行くやり方。SQS はこれ。
サーバーレス
サーバーの管理を自分でしなくていいしくみ。AWS が裏で全部やってくれる。
Amazon SQSシンプル キュー サービス
メッセージをためておくキュー。受け取る側が取りに行く（ポーリング）。疎結合といえば SQS。1つのメッセージは基本1人が処理する。
Amazon SNSシンプル ノーティフィケーション サービス
1つのお知らせをたくさんの相手に一斉に送る（プッシュ）。メール・SMS・SQS・Lambda などに配れる。Pub/Sub 型。
Amazon EventBridgeイベントブリッジ
「〇〇が起きたら△△する」というイベントの交通整理係。AWS のサービスや外部の SaaS で起きた出来事をルールで振り分ける。「毎日9時に実行」のようなスケジュール実行もできる。
AWS Step Functionsステップ ファンクションズ
いくつもの処理を「1→2→3、失敗したらやり直し」と順番どおりに進める司令塔。処理の流れ（ワークフロー）を図で作れる。
Amazon API GatewayAPI ゲートウェイ
外からのリクエストを受け付ける玄関（受付窓口）。API を作って公開・管理できる。API Gateway ＋ Lambda はサーバーレスの定番の組み合わせ。
サービスひとことで送り方たとえ
SQSためておく取りに行く（ポーリング）伝票ホルダー
SNS一斉に配る送りつける（プッシュ）校内放送
EventBridge出来事で振り分けるルールで配る駅の交通整理係
Step Functions手順どおりに進める流れを管理料理のレシピ
API Gateway外からの受付リクエストを受けるお店の玄関・受付
🔑覚え方：SQS は「Q（キュー）＝列に並ぶ」、SNS は「N（ノーティフィケーション）＝お知らせ」

名前のまん中の1文字を見るだけで区別できます。Queue（行列）→ ためる。Notification（通知）→ 一斉に知らせる。

🎯試験に出るポイント
  • 「コンポーネントを疎結合にしたい」「処理が追いつかないときにリクエストをためておきたい」→ SQS
  • 「1つの通知を複数の宛先（メール・SMS など）に送りたい」→ SNS
  • 「AWS で何かが起きたら自動で処理したい」「定期実行したい」→ EventBridge
  • 「複数の Lambda を順番に実行し、エラー時はやり直したい」→ Step Functions

2. 集めて分析する —— データ分析のサービス

データ分析は、「集める → きれいにする → ためる → 調べる → 見える化する」という流れで考えると、サービスの役割が整理できます。

③ ためるS3（データレイク）
Redshift（DWH）

④ 調べるAthena / EMR

「集・清・貯・調・見」の5ステップ。サービスがどこに入るかで覚えます。
📝ことばメモ
ストリーミングデータ
川の流れのように絶えず流れてくるデータ。クリック履歴、センサーの値、ログなど。
ETL
Extract（取り出す）・Transform（形を整える）・Load（入れる）。データを分析しやすい形に加工して運ぶ作業。
データレイク
いろいろな形のデータをそのまま大量にためておく「湖」。AWS では S3 が中心。
DWH（データウェアハウス）
分析用に整理してためたデータの「倉庫」。Redshift がこれ。
SQL
データベースに「こういう条件のデータを出して」とお願いするための言葉。
BI
Business Intelligence。データをグラフやダッシュボード（計器盤のような一覧画面）にして、判断に使うこと。
ビッグデータ
ふつうのコンピューター1台では扱いきれない、とても大量のデータ。
Amazon Kinesisキネシス
リアルタイムに流れてくるデータを集めて処理する。Kinesis Data Streams（流れを受け止める）、Amazon Data Firehose（旧 Kinesis Data Firehose。S3 や Redshift へ自動で運ぶ）、Kinesis Video Streams（動画）がある。
AWS Glueグルー
サーバーレスの ETL サービス。どこにどんなデータがあるかを記録するデータカタログ（データの目録）も持つ。Glue＝「のり」でデータをくっつけるイメージ。
Amazon Athenaアテナ
S3 に置いたデータに、そのまま SQL で質問できる。サーバー不要（サーバーレス）で、調べたデータ量に応じてお金を払う。
Amazon EMRイーエムアール
ビッグデータを、たくさんのサーバーで手分けして処理する。Hadoop や Spark を簡単に使える。
Amazon Redshiftレッドシフト
分析専用のデータウェアハウス。大量のデータを集計するのが得意。くわしくは第5章 データベースへ。
Amazon Quick Sightクイックサイト（旧 Amazon QuickSight）
データをグラフやダッシュボードで見える化する BI サービス。2025年10月に AI 機能などとまとめて Amazon Quick Suite（その後さらに「Amazon Quick」）という名前の製品群になり、BI の部分は「Quick Sight」と呼ばれています。試験問題では「Amazon QuickSight」と書かれることが多いので、どちらの名前でもわかるようにしておきましょう。
Amazon OpenSearch Serviceオープンサーチ
大量のログや文章からすばやく検索・分析する。サイト内検索やログ分析に使う（旧 Elasticsearch Service）。
AWS Lake Formationレイク フォーメーション
データレイクを簡単に作り、だれがどのデータを見てよいか（権限）をまとめて管理する。
🔑覚え方：ギリシャ神話の女神 Athena は「知恵の神」

知恵の神アテナに、湖（S3 データレイク）のほとりで質問（SQL）をすると、すぐ答えてくれる —— という場面を思いうかべます。
Kinesis は「キネマ（映画）」＝ 止まらず流れ続ける映像 → ストリーミング。

⚠️ひっかけ注意
  • Athena（S3 に直接 SQL・サーバーレス）と Redshift（データを入れて大規模に集計する DWH）を混同しない。「S3 のデータをそのまま」「アドホック（その場かぎり）な分析」なら Athena。
  • 「リアルタイム」「ストリーミング」と出たら Kinesis。Glue はバッチ（まとめて処理）向け。
  • 見える化（グラフ）は QuickSight / Quick Sight。CloudWatch のダッシュボード（監視用）とは目的がちがう。

3. AI・機械学習のサービス

AI のサービスは3段の棚に分けて覚えます。上の段ほど「すぐ使える」、下の段ほど「自分で作れる」です。

🍳たとえ話：料理で考える AI
  • 上の段（できあいの AI）＝ お惣菜。買ってきてすぐ食べられる。「画像を見る」「声を文字にする」など、1つの仕事に特化。
  • 中の段（生成 AI）＝ 腕のいいシェフを呼ぶ。Bedrock で有名なシェフ（基盤モデル）を選んで、自分の注文で料理を作ってもらう。
  • 下の段（機械学習を自分で作る）＝ キッチン一式。SageMaker で材料（データ）から自分だけのレシピ（モデル）を作る。
📝ことばメモ
機械学習（ML）
コンピューターに大量のデータを見せて、パターン（規則）を自分で見つけさせる技術。
モデル
機械学習で作られた「判断のしくみ」。データを入れると答え（予測）を出す。
生成 AI
文章・画像・プログラムなどを新しく作り出す AI。ChatGPT や Claude など。
基盤モデル（FM）
大量のデータで前もって学習させた、いろいろな用途に使える大きな AI モデル。生成 AI の土台。
自然言語処理（NLP）
人間がふだん使う言葉（自然言語）をコンピューターが理解・処理すること。
OCR
画像の中の文字を読み取って、テキストデータにする技術。

下の段・中の段：自分で作る／生成 AI

Amazon SageMaker AIセージメーカー
機械学習モデルを作る・学習させる・動かすまで全部できる、開発者・データサイエンティスト向けの台所。（2024年末から「SageMaker AI」という名前になり、「SageMaker」はデータ分析も含む大きなブランド名になりました）
Amazon Bedrockベッドロック
いろいろな会社の基盤モデル（Anthropic の Claude、Amazon Nova など）を、API で呼ぶだけで使える生成 AI サービス。サーバー管理不要。Bedrock＝「岩盤」＝土台。
Amazon Qアマゾン キュー
仕事を手伝ってくれる生成 AI アシスタント。開発者向けの Amazon Q Developer（コードを書く・AWS の使い方を答える）と、社内データをもとに答える Amazon Q Business がある。

🔑覚え方：AI を「顔のパーツ」に置きかえる

👂 耳 ＝ Transcribe（聞いて書く）／ 👄 口 ＝ Polly（しゃべる）
🧠 頭 ＝ Comprehend（意味がわかる）／ 🌐 通訳 ＝ Translate／ 💬 会話 ＝ Lex

自分の顔の、目・耳・口・頭を順番にさわりながら名前を言うと、体の動き（エピソード）と一緒に覚えられます。

🎯試験に出るポイント
  • 「機械学習の知識がなくても」画像認識・翻訳などを使いたい → 上の段（Rekognition・Translate など）
  • 「独自の ML モデルを構築・トレーニング・デプロイしたい」→ SageMaker（AI）
  • 「基盤モデルを使って生成 AI アプリを作りたい」「インフラ管理なしで」→ Bedrock
  • 「コールセンターの通話を文字にして、お客さんの感情を分析」→ Transcribe ＋ Comprehend
⚠️ひっかけ注意

Polly と Transcribe は向きが逆。Polly は「文字→声」、Transcribe は「声→文字」。
Textract と Comprehend もまちがえやすい：Textract は画像から文字を取り出すだけ、Comprehend は文章の意味を理解する。

AWS Database Migration Service（DMS）データベース マイグレーション サービス
データベースを、動かしたまま（止める時間を短く）AWS へ移す。種類のちがう DB への移行もできる。くわしくは第5章へ。

移行のやり方「7つの R」

R意味引っ越しでたとえると
Rehost（リホスト）そのまま移す。リフト＆シフトとも家具をそのままトラックで運ぶ
Replatform（リプラットフォーム）少しだけ手を加えて移す（例：DB を RDS にする）運ぶついでに家電だけ新しくする
Refactor（リファクタリング）クラウド向けに作り直す新しい家に合わせて家具を作り直す
Repurchase（リパーチェス）別の製品（SaaS など）に買い替える古い家具は捨てて新品を買う
Retire（リタイア）使っていないのでやめるいらない物は捨てる
Retain（リテイン）今はまだ移さず残す実家に置いておく
Relocate（リロケート）VMware の環境などを丸ごとクラウドへ移す家ごとクレーンで運ぶ

※昔は Relocate を除いた「6つの R」でした。今は「7つの R」が基本です。

疎結合とは？ ラーメン屋でたとえると？
部品どうしをゆるくつなぎ、片方が止まっても影響が出にくくすること。店員が料理人に手渡しせず、伝票ホルダー（キュー＝SQS）にさしておくイメージ。
SQS と SNS のちがいは？
SQS はメッセージを「ためておく」キュー（受け取る側が取りに行く）。SNS は1つの通知を複数の相手に「一斉に送りつける」（プッシュ、Pub/Sub）。
「複数の処理を順番に実行し、失敗したらやり直す」流れを作るサービスは？
AWS Step Functions。
データ分析の5ステップと、それぞれの代表サービスは？
集める（Kinesis）→ きれいにする（Glue）→ ためる（S3 / Redshift）→ 調べる（Athena / EMR）→ 見える化（QuickSight ＝ 今の Quick Sight）。
S3 のデータに、サーバーなしで直接 SQL を投げられるサービスは？
Amazon Athena（調べたデータ量に応じて課金）。
SageMaker と Bedrock のちがいは？
SageMaker（AI）は自分で ML モデルを作る・学習させる・動かす台所。Bedrock は既製の基盤モデルを API で呼ぶだけで使える生成 AI サービス。
AI を「顔のパーツ」で：目・耳・口・頭はそれぞれどのサービス？
目＝Rekognition（画像・動画）、耳＝Transcribe（声→文字）、口＝Polly（文字→声）、頭＝Comprehend（文章の意味・感情）。
書類の画像から文字や表を取り出すサービスは？
Amazon Textract。
サーバーをそのまま AWS に移す（リホスト）ときのサービスは？ DB を移すときは？
サーバーは AWS Application Migration Service（MGN）、データベースは AWS DMS。全体の進み具合は Migration Hub で見る。
7つの R をできるだけ言ってみよう
Rehost（そのまま）、Replatform（少し変える）、Refactor（作り直す）、Repurchase（買い替える）、Retire（やめる）、Retain（残す）、Relocate（丸ごと移す）。
