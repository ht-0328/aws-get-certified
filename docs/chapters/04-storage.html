第4章 ストレージ（データの置き場所）

写真、書類、バックアップ、サーバーのディスク……。データはどこかに「置く」必要があります。AWS には置き場所がいくつもあり、試験では「この場面ならどれ？」を選ぶ問題がたくさん出ます。

🗺️この章の地図
  1. ストレージの3つの種類（ブロック・ファイル・オブジェクト）
  2. S3 —— なんでも置ける巨大倉庫（ストレージクラス・便利な機能）
  3. EBS とインスタンスストア —— サーバーのディスク
  4. EFS と FSx —— みんなで使う共有フォルダ
  5. 社内とクラウドをつなぐ・データを運ぶ（Storage Gateway・Snow・DataSync・Transfer Family）
  6. まとめてバックアップ（AWS Backup）

1. ストレージの3つの種類

ストレージは、データをどんな形で置くかで3種類に分かれます。AWS のサービスもこの3つにきれいに分かれるので、まずここを押さえましょう。

📦たとえ話：3種類の「しまい方」
  • ブロック＝ 自分専用の机の引き出し。細かく区切られていて、出し入れがとても速い。でも自分（1台のサーバー）しか使えない。
  • ファイル＝ 職場の共有キャビネット。フォルダで整理され、みんな（複数のサーバー）で同時に使える。
  • オブジェクト＝ 巨大な倉庫に預ける荷物。荷物ごとに「荷札（名前と情報）」をつけて丸ごと預ける。量はほぼ無限。インターネットからも取り出せる。

📝ことばメモ
ブロックストレージ

ファイルストレージ
フォルダとファイルで整理するしくみ。会社の共有フォルダ（ネットワークドライブ）と同じ。
オブジェクトストレージ
ファイルを「オブジェクト（データ＋情報のセット）」として丸ごと置くしくみ。中身の一部だけ書きかえることはできず、置き直す。
EC2
AWS で借りるサーバー（くわしくは第3章）。

2. Amazon S3 —— なんでも置ける巨大倉庫

Amazon S3エススリー / Simple Storage Service
インターネット経由で使えるオブジェクトストレージ。容量は実質無限で、置いた分だけ料金がかかる。AWS でいちばん有名なサービスの一つ。
🏬たとえ話：トランクルームの「部屋」と「荷物」

S3 は巨大なトランクルーム。まず自分の部屋（バケット）を借りて、そこに荷物（オブジェクト）を入れます。荷物には荷札（キー＝名前）がついていて、それで取り出します。部屋の名前は世界中でひとつだけ（ほかの人と同じ名前はつけられない）です。

S3 の基本：バケットの中にオブジェクトを入れる

S3 ストレージクラス —— 「よく使う？」で置き場所を変える

S3 には料金と取り出しやすさがちがうストレージクラス（保管プラン）があります。よく使うものは高いけどすぐ出せる棚、めったに使わないものは安いけど出すのに時間がかかる奥の倉庫へ、というイメージです。

🏠たとえ話：家の中の「しまう場所」

標準＝リビングの棚（毎日使う）／標準-IA＝押し入れ（たまに出す）／Glacier＝実家の物置（めったに出さない。取りに行くのに時間がかかる）／Deep Archive＝山奥の貸し倉庫（ほぼ出さない。いちばん安いが、取り出しに半日〜2日）。

S3 の便利な機能

機能なにができる？
ライフサイクル設定「30日たったら標準-IAへ、1年たったら Glacier へ、5年で削除」のように、時間がたったら自動で移動・削除するルール。
バージョニング上書き・削除しても前の版を残しておく。まちがえて消しても元に戻せる。
静的WebサイトホスティングHTML や画像だけの静的なホームページを、サーバーなしで S3 から公開できる。
暗号化2023年からは、新しく置くデータは自動で暗号化（SSE-S3）される。KMS の鍵を使うこと（SSE-KMS）もできる。
ブロックパブリックアクセスバケットがうっかり全世界に公開されるのを防ぐスイッチ。新しいバケットでは最初からオン。
レプリケーション別のバケット（別リージョンも可）へ自動でコピー。災害対策に。

暗号化
データを、鍵を持つ人にしか読めない形に変えること。
SSE
Server-Side Encryption ＝ AWS 側（サーバー側）で暗号化すること。
KMS
Key Management Service。暗号化の「鍵」を管理するサービス（第2章）。
パブリック
Public ＝ だれでも（インターネットの全員が）見られる状態。
🎯試験に出るポイント
  • 「アクセス頻度が予測できない」→ S3 Intelligent-Tiering
  • 「何年も保管、取り出しはまれ、いちばん安く」→ S3 Glacier Deep Archive
  • 「古くなったら自動で安いクラスへ」→ ライフサイクル設定
  • 「まちがって消したファイルを復元したい」→ バージョニング
  • 「サーバーなしで簡単なWebサイトを公開」→ S3 静的Webサイトホスティング
⚠️ひっかけ注意

1ゾーン-IA だけは、データを1つの AZ にしか置きません（ほかのクラスは3つ以上の AZ）。「なくなると困る大事なデータ」に 1ゾーン-IA を選ぶ選択肢は×です。

3. EBS とインスタンスストア —— サーバーのディスク

Amazon EBSイービーエス / Elastic Block Store
EC2 にくっつけて使うブロックストレージ（＝サーバーのディスク）。サーバーを止めてもデータは残る。
💾たとえ話：外付け SSD

EBS はパソコンにつなぐ外付け SSD。パソコン（EC2）の電源を切っても中身は消えないし、別のパソコンにつなぎかえることもできる。ただし同じ部屋（同じ AZ）の中でしか、つなぎかえられません。

インスタンスストア —— 消えてもいい高速ディスク

EC2 の種類によっては、サーバー本体に直接ついているディスク（インスタンスストア）が使えます。とても速いのですが、EC2 を停止・終了すると中身が消えます。一時的な作業用のデータ（キャッシュや計算途中のデータ）向けです。

4. EFS と FSx —— みんなで使う共有フォルダ

Amazon EFSイーエフエス / Elastic File System
Linux サーバー用の共有ファイルストレージ。たくさんの EC2 から同時に使え、複数の AZにまたがる。容量は使った分だけ自動で増減。
Amazon FSxエフエスエックス
有名なファイルシステムを、そのまま AWS で使えるようにしたシリーズ。とくにWindows 用（FSx for Windows File Server）と超高速計算用（FSx for Lustre）が試験に出る。
🗄️たとえ話：共有キャビネット

EFS はどの部屋（AZ）からも開けられる共有キャビネット。中身が増えればキャビネットも勝手に大きくなります。FSx は「Windows 社員用キャビネット」「研究所の超高速キャビネット」のように、使う人に合わせた専用キャビネットです。

5. 社内とクラウドをつなぐ・データを運ぶ

AWS Storage Gatewayストレージゲートウェイ
社内（オンプレミス）のサーバーから、ふつうのファイル置き場やディスクのように見せて、実際は裏で AWS（S3 など）に保存する橋渡し役。ハイブリッドの代表サービス。
種類社内からはこう見える保存先
S3 ファイルゲートウェイ共有フォルダ（NFS/SMB）S3
ボリュームゲートウェイディスク（iSCSI）S3（EBS スナップショットとして）
テープゲートウェイバックアップ用の磁気テープ装置S3 / Glacier
AWS Snow ファミリー（Snowball Edge）スノーボール
ネットで送ると何週間もかかる大量のデータ（数十TB〜PB）を、AWS から届く頑丈な箱型の装置にコピーして、トラックで運ぶサービス。電波の届かない現場でのデータ処理（エッジコンピューティング）にも使える。

※ Snow ファミリーは整理が進んでおり、Snowmobile（トラックそのもの）や Snowcone（小型）はすでに終了、Snowball Edge も2025年以降は新規の受付が限られています。ただし試験では「大量データをオフラインで物理的に運ぶ＝Snowball」というパターンが今も出ることがあるので覚えておきましょう。

AWS DataSyncデータシンク
社内のファイルサーバーなどから、S3・EFS・FSx へネット経由で速く自動でデータを移す・同期するサービス。
AWS Transfer Familyトランスファーファミリー
昔からあるSFTP・FTPS・FTP（ファイルを送る決まりごと）で、S3 や EFS にファイルを出し入れできる窓口。取引先が「FTPでしか送れない」ときに便利。

6. AWS Backup —— バックアップをまとめて管理

AWS Backupエーダブリューエス バックアップ
EBS・EFS・RDS・DynamoDB・FSx などのバックアップを1か所でまとめて計画・実行・管理するサービス。「毎晩2時に取って、35日間残す」のようなルール（バックアッププラン）を作れる。
🎯試験に出るポイント
  • 「複数の EC2（Linux）でファイルを共有」→ EFS／「Windows のファイル共有」→ FSx for Windows File Server
  • 「EC2 を止めても消えないディスク」→ EBS／「一時データで、最高速がほしい」→ インスタンスストア
  • 「社内のアプリから、S3 をふつうのファイル置き場のように使いたい」→ Storage Gateway
  • 「数百TBを、回線が細いので物理的に運びたい」→ Snowball Edge
  • 「いろんなサービスのバックアップを一元管理」→ AWS Backup
⚠️ひっかけ注意
  • EBS はAZ をまたいでそのまま付けかえられない。別 AZ にはスナップショットから作る。
  • 「S3 をサーバーのディスクとして（OS を入れて）使う」はできない。S3 はオブジェクトストレージ。
  • Glacier から取り出すのはすぐではない（Instant Retrieval 以外）。「すぐ必要」なら Glacier Flexible / Deep Archive は×。
