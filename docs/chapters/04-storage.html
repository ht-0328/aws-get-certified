第4章 ストレージ（データの保存先）

データには必ず保存先が必要です。AWS の保存先は3つが中心です。EBS（EC2 1台のディスク）、EFS・FSx（共有フォルダ）、S3（容量無制限のオブジェクト保存）です。試験では要件に合う保存先を1つ選びます。

🧭この章で理解してほしいこと
  • ストレージは「保存する単位」で3種類：要件からサービスが1つに決まる
    • ブロック：1台のサーバーに直結したディスク
      • AWS のサービスで言うと EBS（EC2 につける外付けディスク）
      • 固定長のブロック単位で読み書きする。高速だが原則1台専用
      • 「EC2 1台のディスク」→ EBS
    • ファイル：複数のサーバーで共有するフォルダ
      • AWS のサービスで言うと EFS（Linux 向け）・FSx（Windows 向けなど）
      • フォルダ階層で管理し、ネットワーク越しに同時に使う
      • 「複数の EC2 で共有」→ EFS
    • オブジェクト：データに名前と付随情報を付けて丸ごと保存
      • AWS のサービスで言うと S3
      • HTTP 経由で、容量は実質無制限
      • 一部だけの書き換えはできず、更新は全体を置き換える
      • 「画像やバックアップを大量かつ低コストで」→ S3
    • S3 に OS を入れて EC2 のディスクにすることはできない
  • S3 は容量無制限で、耐久性はイレブンナイン：耐久性と可用性は別の指標
    • バケットという入れ物にオブジェクトを保存する
    • バケット名：全世界の AWS アカウントを通じて一意
    • オブジェクト：1個あたり最大5TB。キー（パスを含む名前）で識別
    • データはリージョン内の複数の AZ に自動で複製される
    • 耐久性：99.999999999%（イレブンナイン）
      • データが失われない度合い。1,000万個で平均1万年に1個
    • 可用性：S3 標準で99.99%
      • 必要なときに使える度合い
      • 「無事だが一時的に取り出せない」は可用性の問題
  • ストレージクラスは、使わないほど安く、遅い：頻繁なら標準、ほぼ参照しないなら Glacier
    1. 標準：頻繁に使うデータ。即時。取り出し料なし
    2. Intelligent-Tiering：頻度が読めないデータ。自動で安い階層へ移す
    3. 標準-IA：低頻度だが即時に取り出す。取り出し料あり。最低30日
    4. 1ゾーン-IA：単一 AZ だけ。失っても作り直せるデータ用
    5. Glacier Instant Retrieval：年に数回だが即時に取り出す。最低90日
    6. Glacier Flexible Retrieval：バックアップ用。取り出しに数分〜12時間
    7. Glacier Deep Archive：長期保管。12〜48時間。最も安い。最低180日
  • S3 の機能は移す・戻す・公開・守る・複製
    • ライフサイクル設定：「30日後に標準-IA、1年後に Glacier、5年後に削除」
    • バージョニング：上書き・削除しても前の版を残す。誤って消しても復元
    • 静的 Web サイトホスティング：サーバーなしで HTML と画像を公開する
    • 暗号化：既定で有効（SSE-S3）。KMS の鍵を使う SSE-KMS も選べる
    • ブロックパブリックアクセス：意図しない公開を防ぐ。新規は既定で有効
    • レプリケーション：別のバケット・別リージョンへ自動複製（災害対策）
    • 1ゾーン-IA を重要データに、「即座に必要」に Glacier の下2つは誤り
  • EBS は AZ に属する。別 AZ へはスナップショット経由：インスタンスストアは停止で消える
    • EBS：ネットワーク経由で EC2 に接続するディスク
      • EC2 を停止してもデータは残る
      • 同じ AZ の別の EC2 に付け替えられる。AZ をまたぐのは不可
      • OS やデータベースなど永続化が必要なデータに使う
    • スナップショット：ある時点のボリュームの複製。S3 に保存される
      • 別の AZ で使うには、スナップショットから新しいボリュームを作る
      • 別リージョンへもコピーできる
    • ボリュームタイプ：gp3（汎用 SSD）、io2（高い I/O 性能を指定できる）
    • インスタンスストア：ホストに直結した高速なディスク
      • 停止・終了すると消える（揮発性）
      • キャッシュや計算途中の一時データ向け
  • 共有は Linux なら EFS、Windows なら FSx：HPC なら FSx for Lustre
    • EFS：Linux 向けの共有ファイルストレージ（NFS）
      • 複数の AZ の多数の EC2 から同時に使える
      • 容量は使用量に応じて自動で伸縮する
    • FSx for Windows File Server：Windows 向け。SMB・Active Directory 連携
    • FSx for Lustre：高性能計算（HPC）・機械学習向け。S3 と連携
    • FSx for NetApp ONTAP / OpenZFS：オンプレミスと同じ製品をそのまま移す
    • EBS は「1台専用・単一 AZ」、EFS は「複数台で共有・マルチ AZ」
  • オンプレ連携は Storage Gateway・DataSync・Snowball：継続利用・回線で移す・物理で運ぶ
    • Storage Gateway：オンプレミスからは普通のファイル共有やディスクに見える
      • 実体は S3 などに保存する。ハイブリッド構成の代表
      • S3 ファイル（NFS/SMB）・ボリューム（iSCSI）・テープの3種類
    • DataSync：ネットワーク経由で S3・EFS・FSx へ高速に移行・同期する
    • Snowball Edge：物理デバイスにコピーして配送で移す
      • 数十 TB〜PB など、回線では数週間以上かかる場合に使う
      • 縮小中だが、試験では「オフラインで移送＝Snowball」で出る
    • Transfer Family：SFTP・FTPS・FTP で S3・EFS にファイルを送受信する
  • バックアップの一元管理は AWS Backup：ディスク・共有フォルダ・データベースをまとめて
    • 対象は EBS・EFS・FSx（この章）、RDS・DynamoDB（第5章のデータベース）など
    • 「毎日2時に取得し、35日間保持する」のようなプランを定義する

読み終えたら、本文を見ずに各項目を自分の言葉で説明できるか確かめてください。

1. ストレージの3つの種類

ストレージは、データをどのような単位で保存・管理するかによって3種類に分類されます。AWS のストレージサービスもこの分類に沿って整理できるため、最初に押さえておきます。

💡イメージで理解する
  • ブロック：1台のサーバーに直結したディスク。データを固定長のブロック単位で読み書きするため高速だが、原則として1台のサーバーから利用する。
  • ファイル：社内の共有フォルダに相当。フォルダ階層でファイルを管理し、複数のサーバーから同時にアクセスできる。
  • オブジェクト：データ本体に名前（キー）と付随情報（メタデータ）を付けて丸ごと保管する方式。容量の上限が実質なく、HTTP（インターネット）経由で読み書きする。

試験では「EC2 1台のディスク」→ EBS、「複数の EC2 で共有」→ EFS、「画像やバックアップを大量かつ低コストで保存」→ S3 という対応がよく問われます。
📝用語の補足
ブロックストレージ
データを固定長のブロックに分けて保存する方式。PC に内蔵された SSD と同じ扱いで、低遅延だが基本的に1台専用。
ファイルストレージ
フォルダとファイルの階層構造で管理する方式。ネットワーク越しに複数台で共有できる。
オブジェクトストレージ
データ本体・メタデータ・キーを1つの「オブジェクト」として保存する方式。一部だけの書き換えはできず、更新時はオブジェクト全体を置き換える。
EC2
AWS の仮想サーバー（詳細は第3章）。

2. Amazon S3 —— 容量無制限のオブジェクトストレージ

Amazon S3エススリー / Simple Storage Service
インターネット経由で利用するオブジェクトストレージ。容量は実質無制限で、保存した量に応じて課金される。AWS の中でも利用範囲が最も広いサービスの一つ。

S3 では、まずバケットという入れ物を作成し、その中にオブジェクト（ファイル）を保存します。各オブジェクトはキー（パスを含む名前）で一意に識別されます。バケット名は全世界の AWS アカウントを通じて一意でなければなりません。

S3 ストレージクラス —— アクセス頻度に応じて保存先を選ぶ

S3 には、保管料金と取り出しの速さ・費用が異なるストレージクラスが用意されています。原則として、アクセス頻度の高いデータは保管料が高く取り出しが速いクラスに、ほとんど参照しないデータは保管料が安く取り出しに時間や費用がかかるクラスに置きます。

クラス想定する用途取り出し注意点

Infrequent Access の略。「アクセス頻度が低い」という意味。
Glacier（グレイシャー）

🔑覚え方：「標・イン・IA・1・Glacier」の順に安く、遅くなる

下に行くほど保管料が安く、取り出しが遅く（または高く）なる：
標準 → インテリジェント → 標準-IA → 1ゾーン-IA → Glacier（Instant → Flexible → Deep Archive）

Glacier の3クラスは、取り出し時間が「即時 → 数分〜数時間 → 12時間以上」の順。名前の「Deep（深い）」が最も取り出しに時間がかかると対応づけておくと整理しやすくなります。

S3 の主な機能

🎯試験での問われ方
  • 「アクセス頻度が予測できない」→ S3 Intelligent-Tiering
  • 「長期保管、取り出しはまれ、最も低コスト」→ S3 Glacier Deep Archive
  • 「一定期間が過ぎたら自動で安価なクラスへ移す」→ ライフサイクル設定
  • 「誤って削除・上書きしたファイルを復元したい」→ バージョニング
  • 「サーバーを使わずに静的な Web サイトを公開」→ S3 静的 Web サイトホスティング
⚠️間違えやすい点

1ゾーン-IA だけは、データを単一の AZ にしか保存しません（他のクラスは複数の AZ に保存）。「失うと業務に支障がある重要データ」の保存先として 1ゾーン-IA を選ぶ選択肢は誤りです。

3. EBS とインスタンスストア —— EC2 のディスク

Amazon EBSイービーエス / Elastic Block Store
EC2 に接続して使うブロックストレージ（EC2 のディスク）。EC2 を停止してもデータは保持される。

EBS は、ネットワーク経由で EC2 に接続する外付けディスクに相当します。EC2 から切り離して別の EC2 に付け替えることもできますが、付け替えられるのは同じ AZ 内の EC2 に限られます。

インスタンスストア —— 揮発性の高速ディスク

一部の EC2 インスタンスタイプでは、ホストサーバーに物理的に直結したディスク（インスタンスストア）を利用できます。非常に高速ですが、EC2 を停止・終了すると内容が消去されます（揮発性）。キャッシュや計算途中の一時データの保存に向いています。

4. EFS と FSx —— 共有ファイルストレージ

Amazon EFSイーエフエス / Elastic File System
Linux 向けのフルマネージドな共有ファイルストレージ。多数の EC2 から同時にマウントでき、複数の AZ にまたがって利用できる。容量は使用量に応じて自動で増減する。
Amazon FSxエフエスエックス
広く使われている商用・オープンソースのファイルシステムを、マネージドサービスとして提供するシリーズ。試験では特にWindows 向け（FSx for Windows File Server）とHPC 向け（FSx for Lustre）が問われる。

EFS は Linux サーバー群が共通で使うファイル領域で、保存量に合わせて容量が自動的に拡張・縮小します。FSx は、Windows 環境や高性能計算など特定の用途・既存製品との互換性が求められる場合に選択します。

EFS のプロトコルは NFS（Linux 標準）、FSx for Windows は SMB（Windows 標準）。「EFS と NFS」「Windows と SMB」のように、サービスとプロトコルを組で覚えます。Lustre は「HPC・機械学習」とセットで覚えておけば十分です。

5. オンプレミスとの連携・データ移行

AWS Storage Gatewayストレージゲートウェイ
オンプレミスのサーバーからは通常のファイル共有やディスクとして見え、実体は AWS（S3 など）に保存する仕組み。ハイブリッドクラウド構成の代表的なサービス。

AWS Snow ファミリー（Snowball Edge）スノーボール
ネットワーク経由では転送に数週間以上かかる大容量データ（数十 TB〜PB 規模）を、AWS から送付される堅牢な物理デバイスにコピーし、配送によってAWS へ移すサービス。通信環境の乏しい現場でのデータ処理（エッジコンピューティング）にも使われる。

※ Snow ファミリーは縮小が進んでおり、Snowmobile（トラック型）と Snowcone（小型）は提供を終了し、Snowball Edge も2025年以降は新規受付が限定されています。ただし試験では「大容量データをオフラインで物理的に移送する＝Snowball」という出題が引き続き見られるため、対応関係は押さえておきます。

6. AWS Backup —— バックアップの一元管理

AWS Backupエーダブリューエス バックアップ
EBS・EFS・RDS・DynamoDB・FSx などのバックアップを一元的に計画・実行・管理するサービス。「毎日2時に取得し、35日間保持する」といったルール（バックアッププラン）を定義できる。
🎯試験での問われ方
  • 「複数の Linux EC2 でファイルを共有」→ EFS／「Windows のファイル共有」→ FSx for Windows File Server
  • 「EC2 を停止してもデータが残るディスク」→ EBS／「一時データ用で、最高の I/O 性能が必要」→ インスタンスストア
  • 「オンプレミスのアプリから S3 を通常のファイル共有として使いたい」→ Storage Gateway
  • 「回線帯域が不足しており、数百 TB を物理的に移送したい」→ Snowball Edge
  • 「複数サービスのバックアップを一元管理したい」→ AWS Backup
⚠️間違えやすい点
  • EBS はAZ をまたいで直接付け替えることはできません。別の AZ ではスナップショットから作成し直します。
  • S3 を EC2 のディスクとして（OS をインストールして）使うことはできません。S3 はオブジェクトストレージです。
  • Glacier からの取り出しは、Instant Retrieval を除き即時ではありません。「即座に必要」という要件で Glacier Flexible Retrieval / Deep Archive を選ぶのは誤りです。

🧠 想起練習

本文を見ずに答えを思い出してから、各項目を開いて確認してください。

ストレージの3分類と、それぞれに対応する AWS の代表サービスは？
ブロック＝EBS、ファイル＝EFS / FSx、オブジェクト＝S3。
S3 の「バケット」と「オブジェクト」とは何か。バケット名にはどのような制約があるか。
バケット＝オブジェクトを格納する入れ物、オブジェクト＝保存する個々のデータ（1個最大5TB）。バケット名は全世界で一意でなければならない。
S3 の耐久性は何%で、何と呼ばれるか。
99.999999999%（イレブンナイン）。
アクセス頻度が予測できないデータに適した S3 のストレージクラスは？
S3 Intelligent-Tiering（アクセス状況に応じて自動で階層を移動する）。
最も安価だが、取り出しに12時間以上かかるストレージクラスは？
S3 Glacier Deep Archive。
「30日後に標準-IA、1年後に Glacier へ自動移行」を実現する機能は？
ライフサイクル設定（ライフサイクルルール）。
誤って削除・上書きしたオブジェクトを復元できるようにする機能は？
バージョニング。
EBS とインスタンスストアの最も大きな違いは？
EC2 を停止・終了したとき、EBS のデータは残るが、インスタンスストアのデータは消える。
EBS ボリュームを別の AZ で使うにはどうするか。
スナップショットを取得し、そこから別の AZ に新しいボリュームを作成する。
EFS と FSx for Windows File Server はどう使い分けるか。
EFS＝Linux（NFS）での共有、FSx for Windows＝Windows（SMB・Active Directory 連携）での共有。
Storage Gateway・DataSync・Snowball はどう使い分けるか。
Storage Gateway＝オンプレミスから AWS を継続的に利用するハイブリッド構成、DataSync＝ネットワーク経由の移行・同期、Snowball＝大容量データを物理デバイスで移送。
