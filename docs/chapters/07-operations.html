1. 見張りの3兄弟：CloudWatch・CloudTrail・Config

名前が似ていていちばんまちがえやすいところです。グループ分類法で、3つまとめて「何を見張るか」のちがいで覚えましょう。

🏬たとえ話：お店の見張り
  • CloudWatch＝ 体温計・血圧計と警報ベル。「サーバーの調子（CPU が何%か）」をはかり、悪くなったらベルを鳴らす。
  • CloudTrail＝ 防犯カメラ。「だれが・いつ・何をしたか」（どの操作をしたか）を録画する。
  • Config＝ お店の配置の記録写真と、ルールのチェック係。「棚がいつどう変わったか」を記録し、「非常口の前に物を置かない」などのルールを守れているかチェックする。
サービス何を見る？こんな質問に答える
CloudWatch性能・状態（数値やログ）「CPU 使用率は今どれくらい？」「高くなったら知らせて」
CloudTrail操作の記録（API の呼び出し）「だれがこの EC2 を消したの？」
Config設定とその変化「このセキュリティグループの設定はいつ・どう変わった？」「ルール違反の設定はある？」
🔑覚え方：「ウォッチは体、トレイルは足あと、コンフィグは設定」

Watch（見る）＝ 体調を見る。
Trail（足あと・小道）＝ だれかが歩いた足あとが残る。
Config（configuration＝設定）＝ 設定そのもの。
英語の意味がそのままヒントになっています。

2. まとめて管理する：Systems Manager

AWS Systems Managerシステムズマネージャー
たくさんのサーバー（EC2 や会社のサーバー）をまとめて操作・管理する道具箱。たとえば：
・Session Manager：SSH の鍵やポートを開けずに、ブラウザから安全にサーバーへログイン
・Patch Manager：パッチ（修正プログラム）を一斉にあてる
・Run Command：たくさんのサーバーに同じ命令を一度に送る
・Parameter Store：設定値やパスワードを安全にしまっておく

3. 自動で作る：CloudFormation と CDK

画面でポチポチ作ると、同じものをもう一度作るのが大変で、まちがいも起きます。そこでインフラの設計図を文字（コード）で書いて、自動で作る考え方が生まれました。これを IaC（アイエーシー）といいます。

🧱たとえ話：レゴの組み立て説明書

CloudFormation はレゴの説明書。説明書（テンプレート）があれば、だれが何度作っても同じ形ができる。できあがった作品（まとまり）をスタックと呼び、まとめてこわす（削除する）こともできる。

テンプレート設計図（YAML/JSON）
→
CloudFormation説明書どおりに組み立て
→
スタックVPC・EC2・RDS…のセット
同じテンプレートで「開発用」「本番用」「別のリージョン」に、同じ環境をすぐ作れます。
AWS CloudFormationクラウドフォーメーション
テンプレート（YAML か JSON）に書いた AWS リソースを自動で作る。CloudFormation 自体は無料（作ったリソースの料金だけかかる）。
AWS CDKCloud Development Kit
Python や TypeScript などのふつうのプログラミング言語で設計図を書ける。書いたものは裏で CloudFormation のテンプレートに変換される。
（参考）Elastic Beanstalk
プログラムを渡すだけで、サーバーなどを自動で用意してくれる PaaS。「インフラを気にせずアプリを動かしたい」ならこちら、「インフラをコードで細かく管理したい」なら CloudFormation。

4. アドバイスとお知らせ

AWS Trusted Advisorトラステッドアドバイザー
あなたの AWS の使い方を見て、「ここをこうするともっといいですよ」とアドバイスしてくれる。5つの分野：コスト最適化・パフォーマンス・セキュリティ・耐障害性・サービスの制限（上限）（＋運用上の優秀性）。全部のチェックを使うには Business 以上のサポートプランが必要。
🔑覚え方：Trusted Advisor の5分野「コ・パ・セ・た・せ」

コスト／パフォーマンス／セキュリティ／耐障害性／サービス制限 → 「こぱせ たせ（こっぱ、ちゃんと足せ）」—— アドバイザーが「小銭をちゃんと足せ」と言っている場面を思いうかべる。

AWS Health Dashboardヘルスダッシュボード
AWS 側で起きている障害やメンテナンスのお知らせを見る画面。とくに「あなたのリソースに関係のある」お知らせを教えてくれる。
AWS X-Rayエックスレイ
アプリの中で、リクエストがどこを通って、どこで時間がかかったかをレントゲンのように見る。たくさんの部品に分かれたアプリ（マイクロサービス）の「どこがおそいか」探しに使う。

5. たくさんのアカウントを管理する

AWS Organizationsオーガニゼーションズ
たくさんの AWS アカウントを1つのグループにまとめる。一括請求（請求書を1枚にまとめ、使用量合算で割引も受けやすい）と、SCP（サービスコントロールポリシー）で「この部署のアカウントではこのサービス禁止」のような制限ができる。くわしくは 第2章。
AWS Control Towerコントロールタワー
複数アカウントの環境（ランディングゾーン）を、ベストプラクティスどおりに自動で組み立てる。Organizations の上に乗る「空港の管制塔」。
AWS Service Catalogサービスカタログ
会社が「使ってよい」と認めた構成だけをカタログ（メニュー表）にして、社員はそこから選んで使う。社食のメニュー表のイメージ。

6. よい設計の教科書：Well-Architected フレームワーク

AWS Well-Architected フレームワークウェルアーキテクテッド
AWS が長年の経験からまとめた「よい設計」の考え方。6つの柱からなる。Well-Architected Tool を使うと、質問に答えるだけで自分の設計をチェックできる（無料）。
#柱ひとことで
1運用上の優秀性
Operational Excellence		うまく運用し、改善し続ける（自動化・小さな変更をこまめに）
2セキュリティ
Security		データとシステムを守る（最小権限・暗号化・記録）
3信頼性
Reliability		こわれても自動で立ち直る（マルチAZ・バックアップ）
4パフォーマンス効率
Performance Efficiency		目的に合ったサービスを選び、速く動かす
5コスト最適化
Cost Optimization		ムダなお金を使わない
6サステナビリティ
Sustainability		環境への負荷（電気の使いすぎなど）を減らす
🔑覚え方：「運・セ・信・パ・コ・サ」

勉強法のページでも出てきた頭字法です。「うん、せしん（世心）ぱこさ」。6番目のサステナビリティは 2021 年に追加された新しい柱、とセットで覚えましょう。

⚠️ひっかけ注意
  • CloudWatch と CloudTrail：「性能の監視」なら Watch、「だれが操作したか」なら Trail。名前の Cloud にまどわされない。
  • Config と CloudTrail：Config は「設定がどう変わったか」、CloudTrail は「だれが操作したか」。両方を組み合わせて調べることも多い。
  • Trusted Advisor と Well-Architected Tool：Trusted Advisor は自動で実際の環境を点検、Well-Architected Tool は質問に答えて設計を見直す。
  • Health Dashboard と CloudWatch：AWS 側の障害情報は Health Dashboard、自分のリソースの数値は CloudWatch。
