第6章 ネットワーク

ネットワークの設計では、サーバーやデータベースを「どこに配置するか」と「どの通信を許可するか」を決めます。SAA では最も重要な分野の一つであり、CLF でも VPC とセキュリティグループは頻出です。

1. 前提知識：IP アドレスと CIDR

ネットワーク上の各コンピューターには、通信相手を特定するための番号が割り当てられています。これを IP アドレスといいます。

また、連続した IP アドレスの範囲をまとめて表す表記法が CIDR（サイダー）です。

💡イメージで理解する

CIDR は住所の「地域の範囲指定」に近いものです。10.0.0.0/16 が市全体を指すとすれば、10.0.1.0/24 はその中の一つの町域にあたります。
/ の後の数値が大きいほど、範囲は狭くなります（/16 は 65,536 個、/24 は 256 個のアドレス）。

表記アドレス数主な用途
10.0.0.0/1665,536 個VPC 全体
10.0.1.0/24256 個
うち 5 個は AWS が予約するため、利用できるのは 251 個		サブネット
📝用語の補足
IP アドレス
ネットワーク上の機器を識別する番号。パブリック IP はインターネットから到達可能なアドレス、プライベート IP は内部ネットワークでのみ使うアドレス。
CIDR
IP アドレスの範囲の表記法。プレフィックス長（/ の後の数値）が大きいほど範囲が狭い。
ルーティング
データを宛先へ届けるために、どの経路を通すかを決定すること。

2. VPC：AWS 上に作る専用ネットワーク

Amazon VPCVirtual Private Cloud
AWS 上に作成する、論理的に分離された自分専用のネットワーク。他のユーザーのネットワークとは隔離される。1 つのリージョン内に作成し、そのリージョンの複数の AZ にまたがって利用できる。
💡イメージで理解する

VPC は、オフィスビルの構成に置き換えると全体像をつかみやすくなります。

  • VPC：AWS 上に確保した自社専用の建物。
  • サブネット：建物内のフロア。外部の来訪者を受け入れるフロア（パブリック）と、関係者のみが立ち入るフロア（プライベート）に分ける。
  • インターネットゲートウェイ：外部との出入口。
  • NAT ゲートウェイ：内部から外部へ出ることだけを許す出口。外部からの進入はできない。
  • ルートテーブル：各フロアに掲示された経路の案内（「外部宛てはインターネットゲートウェイへ」など）。

通信の流れ：利用者 → インターネットゲートウェイ（IGW）→ ALB → EC2 → RDS。EC2 と RDS はプライベートサブネットに配置するため、インターネットから直接アクセスされません。
EC2 がソフトウェアの更新などで外部へ接続する場合は、NAT ゲートウェイを経由します。

パブリックサブネットとプライベートサブネットの違い

サブネット自体に「公開／非公開」の設定項目があるわけではありません。そのサブネットに関連付けたルートテーブルに、「0.0.0.0/0（インターネット宛て）はインターネットゲートウェイへ」という経路があるかどうかで決まります。

種類ルートテーブルの内容配置するリソース
パブリックサブネット0.0.0.0/0 → インターネットゲートウェイロードバランサー、NAT ゲートウェイ、踏み台サーバー
プライベートサブネット0.0.0.0/0 → NAT ゲートウェイ（または外部への経路なし）アプリケーションサーバー（EC2）、データベース（RDS）

0.0.0.0/0 は「すべての IPv4 アドレス」、つまりインターネット上の任意の宛先を意味します。

インターネットゲートウェイ（IGW）
VPC とインターネットを接続するコンポーネント。VPC に 1 つアタッチする。受信と送信の両方が可能。
NAT ゲートウェイ
プライベートサブネットのリソースが外部へ接続するための送信専用の経路。外部から内部への接続は受け付けない。パブリックサブネットに配置する。AZ ごとに配置すると、1 つの AZ で障害が起きても影響を受けにくい。
NAT：アドレス変換の仕組み。
🔑覚え方：「IGW は送受信、NAT は送信のみ」

IGW＝受信・送信（パブリックサブネット用）／NAT＝送信のみ（プライベートサブネット用）。
NAT ゲートウェイは「プライベートのリソースが使う」が「パブリックに置く」点もあわせて押さえておきます。

3. 2種類のファイアウォール：セキュリティグループとネットワーク ACL

VPC には、通信を許可・拒否する仕組み（ファイアウォール）が 2 種類あります。両者の比較は試験で頻出です。

💡イメージで理解する
  • セキュリティグループは個々のサーバー（インスタンス）の入口で働くチェック機能です。一度許可した通信を記録しているため、その応答は改めて確認せずに通します。ルールには「許可するもの」だけを記述します。
  • ネットワーク ACL はサブネットの境界で働くチェック機能です。通信の状態を記録しないため、往路と復路をそれぞれ検査します。ルールには許可と拒否の両方を記述でき、番号の小さいルールから順に評価されます。
セキュリティグループ（SG）ネットワーク ACL（NACL）
適用単位インスタンス（正確にはネットワークインターフェース）サブネット
ルール許可のみ許可と拒否
状態の保持ステートフル（応答は自動的に許可）ステートレス（応答も別途許可が必要）
評価方法すべてのルールを総合して判断番号の小さい順に評価し、最初に一致したルールを適用
初期状態インバウンド：すべて拒否／アウトバウンド：すべて許可デフォルト NACL はすべて許可
🔑覚え方：SG は「イ・キョ・フル」

SG：インスタンス単位／許可のみ／ステートフル。
NACL はそのすべてが逆（サブネット単位／許可と拒否／ステートレス）です。片方を確実に覚えれば、もう片方は導き出せます。

🎯試験での問われ方
  • 「特定の IP アドレスからの通信を拒否したい」→ ネットワーク ACL（SG には拒否ルールがない）
  • 「Web サーバーへは 443 番ポート（HTTPS）のみ許可したい」→ セキュリティグループ
  • 「DB へは Web サーバーからの接続のみ許可したい」→ DB の SG のソースに「Web サーバーの SG」を指定する（SG は送信元として別の SG を指定できる）
  • 「プライベートサブネットの EC2 からインターネット上の更新プログラムを取得したい」→ NAT ゲートウェイ

4. VPC 同士、VPC と AWS サービスの接続

VPC ピアリングPeering
2 つの VPC を1 対 1 で直接接続する。別アカウント・別リージョンの VPC とも接続できる。ただし推移的なルーティングはできない（A–B、B–C が接続されていても、A から C へは通信できない）。CIDR が重複している VPC 同士は接続できない。
AWS Transit Gateway
多数の VPC やオンプレミスネットワークを、中央のハブを介してまとめて接続する。航空網のハブ空港と同じ考え方。接続する VPC が多い場合は、ピアリングを個別に張るよりも管理が容易になる。

VPC エンドポイント
VPC 内から S3 などの AWS サービスへ、インターネットを経由せずに接続するための仕組み。2 種類ある。
・ゲートウェイ型：S3 と DynamoDB 専用。追加料金なし。
・インターフェース型：多くのサービスに対応。実体は AWS PrivateLink。
AWS PrivateLink
AWS のサービスや、他のアカウントの VPC で提供されているサービスを、自分の VPC 内のプライベート IP アドレス経由で安全に利用できるようにする仕組み。

5. オンプレミスとの接続

Site-to-Site VPNインターネット上に暗号化された通信経路（トンネル）を構築するインターネットの混雑状況に左右される短い（数分〜数時間）

💡イメージで理解する

VPN は、公道（インターネット）の上に、外部から中身が見えない専用レーンを設けるようなものです。すぐに用意できますが、道路全体が混雑すれば影響を受けます。
Direct Connect は、自社から AWS まで私道を敷設するようなものです。工事に時間はかかりますが、他の交通の影響を受けず、安定した通信が得られます。

6. 利用者からのアクセスの制御と高速化

Amazon Route 53
マネージド型の DNS サービス。ドメイン名に対応する IP アドレスを応答する。ドメインの登録や、接続先が正常に動作しているかを確認するヘルスチェックも提供する。名称の「53」は DNS が使うポート番号に由来する。
ルーティングポリシー概要
シンプル単一の応答を返す
加重（Weighted）「新バージョンに 10%、旧バージョンに 90%」のように比率で振り分ける
レイテンシー利用者にとって最も遅延の小さいリージョンへ振り分ける
フェイルオーバープライマリに障害が起きたらセカンダリへ切り替える（ヘルスチェックと併用）
位置情報（Geolocation）利用者の国・地域に応じて振り分ける（例：日本からのアクセスは日本語サイトへ）
地理的近接性・複数値回答・IP ベース距離に応じた振り分け／複数の応答を返す／送信元 IP の範囲による振り分け
Amazon CloudFront
CDN サービス。世界中のエッジロケーションに画像・動画・Web ページをキャッシュし、利用者の近くから配信する。S3 や ALB などを配信元（オリジン）に指定する。DDoS 対策の Shield Standard が自動で適用され、WAF と組み合わせることもできる。
AWS Global Accelerator
利用者の通信を最寄りのエッジロケーションから AWS のグローバルネットワーク（バックボーン）に乗せ、アプリケーションまで高速に届ける。固定の IP アドレスが 2 つ割り当てられる。キャッシュは行わない。ゲームや VoIP など TCP/UDP を使う通信や、迅速なフェイルオーバーが必要な場合に使う。

ロードバランサー（ELB：ALB・NLB など）は、複数のサーバーに処理を分散させる仕組みです。詳しくは 第3章 コンピューティング を参照してください。

⚠️間違えやすい点
  • CloudFront と Global Accelerator：どちらもエッジロケーションを使うが、CloudFront はキャッシュする／Global Accelerator はキャッシュしない。「固定 IP が必要」「HTTP 以外のプロトコル」なら Global Accelerator。
  • NAT ゲートウェイはパブリックサブネットに配置する（利用するのはプライベートサブネットのリソースだが、配置先はパブリック）。
  • VPC ピアリングは推移的なルーティングができない。
  • SG には拒否ルールがない。設問に「拒否」とあれば NACL を検討する。
