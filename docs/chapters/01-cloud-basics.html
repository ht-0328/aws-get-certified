第1章 クラウドとAWSの全体像

クラウドとは、AWS のサーバーなどを必要な分だけ使い、使った分だけ払う形態です。AWS はその設備を世界各地のリージョンに置き、複数の AZ に分けて障害に耐えます。以降のすべての章の前提です。

🧭この章で理解してほしいこと
  • 違いは「設備を買う」か「使った分だけ払う」か：オンプレミスは買う、クラウドは借りる
    • オンプレミス：自社でサーバーを買い、自社の施設に置いて保守する
    • クラウド：AWS の資源を必要な量だけ使い、使った分だけ払う（従量課金）
    • 自家発電設備を持つか、電力会社から電気を買うかの違い
    • 違いは4つ
      • 費用：設備の購入費（固定費）→ 使った分の料金（変動費）
      • 用意する時間：調達・設置を待つ → 数分で起動
      • 保守：故障対応・電源・空調を自社で → AWS が行う
      • 不要になったとき：設備が残る → すぐ解放して料金も止まる
  • 6つの利点は「お金の3つ」と「速さの3つ」：試験では6つをそのまま問われる
    1. 固定費を変動費に変える（買わずに借りる）
    2. 規模の経済の恩恵を受ける（まとめ買いで単価が安い）
    3. キャパシティの予測が不要になる（余らせない・足りなくならない）
    4. 速度と俊敏性を向上させる（数分で用意できる）
    5. データセンターの運用・保守への投資が不要になる（面倒を見なくていい）
    6. 数分で世界中に展開できる（どこにでもすぐ出せる）
  • IaaS・PaaS・SaaS は「任せる範囲」の違い：任せるほど楽になり、自由度は下がる
    • IaaS：サーバーやネットワークなどの基盤を借りる
      • AWS のサービスで言うと EC2（仮想サーバー）・EBS（そのディスク）
      • VPC（自分専用のネットワーク）も IaaS にあたる
      • OS から上（OS・ミドルウェア・アプリ・データ）は利用者が管理する
    • PaaS：アプリの実行環境まで借りる
      • AWS のサービスで言うと Elastic Beanstalk（Web アプリの実行環境を自動で用意）
      • Beanstalk にコードを渡すと、裏で EC2・ELB・Auto Scaling を作って動かす
      • EC2 には OS・言語（Java など）・Web サーバーが入った状態で用意される
      • RDS（運用を任せられるデータベース）も PaaS にあたる
      • 利用者が管理するのはアプリとデータだけ
    • SaaS：完成したソフトをそのまま使う
      • AWS のサービスで言うと WorkMail（メール）・WorkSpaces（仮想デスクトップ）
      • 一般の例は Gmail・Microsoft 365
      • 利用者が管理するのはデータと利用設定だけ
    • 試験では「利用者が管理するのはどこまでか」を問われる
    • デプロイモデルは置き場所の違い
      • クラウド：すべてクラウドに作る
      • ハイブリッド：オンプレミスとクラウドを接続して併用する
      • オンプレミス：すべて自社設備（プライベートクラウド）
  • リージョン ⊃ AZ ⊃ データセンター：止めないなら複数の AZ に分けて置く
    • リージョン：東京・大阪・バージニア北部などの地理的な地域
      • リージョン同士は互いに独立している
      • データは利用者が動かさない限り他のリージョンへ移らない
    • AZ：リージョン内の独立したデータセンターの区画
      • 1リージョンに原則3つ以上。電源もネットワークも独立
      • AZ 間は低遅延の専用回線でつながる
    • マルチ AZ：複数の AZ に分散して置く構成
      • 1つの AZ が止まっても他の AZ で動き続ける（高可用性）
      • 「1つのデータセンターが止まっても止めない」の答え
    • エッジロケーション：利用者の近くに置いた小規模な拠点
      • CloudFront（キャッシュ配信）と Route 53（DNS）が使う
      • 「海外の利用者に低遅延で配信したい」の答え
      • 複数のリージョンに置くのも答え。ELB はリージョンをまたげない
  • リージョン選びは「置ける？ 近い？ 使える？ 安い？」：AZ の数は基準でない
    1. 置ける？：法令・規制。国内に置く義務があれば選べる場所が限られる
    2. 近い？：利用者との距離（レイテンシー）。近いほど応答が速い
    3. 使える？：サービスの提供状況。新しいサービスは一部のリージョンだけ
    4. 安い？：価格。同じサービスでもリージョンで料金が違う
  • 操作方法は3つ：どれも同じ AWS の API を呼んでいる
    • マネジメントコンソール：ブラウザの画面で操作する
    • CLI：コマンドで操作する。スクリプトにして自動化しやすい
    • SDK：Python や Java のプログラムから操作する
    • CLI・SDK はアクセスキー ID とシークレットアクセスキーで認証する

読み終えたら、本文を見ずに各項目を自分の言葉で説明できるか確かめてください。

1. クラウドとは何か

企業が業務システムを運用する方法として、従来は自社でサーバーを購入し、自社の施設に設置して運用する形態が一般的でした。これをオンプレミスと呼びます。

これに対しクラウド（クラウドコンピューティング）は、AWS のような事業者が保有するコンピューティング資源を、インターネット経由で、必要なときに必要な量だけ利用し、利用量に応じて料金を支払う形態です。

💡イメージで理解する

オンプレミスとクラウドの関係は、自家発電設備を持つことと電力会社から電気を購入することの関係に近いものです。自家発電では設備の購入費が先にかかり、保守や故障対応も自社で行う必要があります。電力会社から購入する場合は、設備の運用を事業者に任せ、使用量に応じた料金だけを支払います。

2. クラウドコンピューティングの6つの利点

AWS はクラウドコンピューティングの利点を6つに整理しています。試験でそのまま問われるため、6つすべてを挙げられるようにしてください。

#利点（公式の表現）意味
1固定費を変動費に変える設備への先行投資の代わりに、利用量に応じた費用を支払う。
固定費：利用量にかかわらず発生する費用。変動費：利用量に応じて増減する費用。
2規模の経済の恩恵を受けるAWS が膨大な数の利用者の需要を集約して調達・運用するため、単価が下がり、利用者は低い料金で利用できる。
規模の経済：生産・調達の規模が大きいほど、1単位あたりのコストが下がること。
3キャパシティの予測が不要になる必要な処理能力を事前に見積もらなくてよい。需要に応じて増減できるため、過剰投資や容量不足を避けられる。
キャパシティ：システムが処理できる量や容量。
4速度と俊敏性を向上させるIT リソースを数分で用意できるため、開発や検証のサイクルを短縮できる。
俊敏性（アジリティ）：変化に迅速に対応できる能力。
5データセンターの運用・保守への投資が不要になる施設・電源・空調・ハードウェアの管理を AWS に任せ、自社の事業に注力できる。
6数分で世界中に展開できる世界各地のリージョンにシステムを短時間で展開し、各地の利用者に低遅延でサービスを提供できる。
🔑覚え方：「お金の3つ」と「速さの3つ」を、ふだんの言葉で
  • お金の3つ
    • 買わずに借りる → ①固定費を変動費に変える
    • まとめ買いで安い → ②規模の経済の恩恵を受ける
    • 余らせない・足りなくならない → ③キャパシティの予測が不要
  • 速さの3つ
    • すぐ作れる → ④速度と俊敏性を向上させる
    • 面倒を見なくていい → ⑤データセンターの運用・保守への投資が不要
    • どこにでもすぐ出せる → ⑥数分で世界中に展開できる
  • 思い出すときは「お金で3つ、速さで3つ」と数を先に決める
🎯試験での問われ方
  • 「初期投資を抑え、使用した分だけ支払いたい」→ 固定費を変動費に変える
  • 「需要が予測できない」「アクセス量の変動が大きい」→ キャパシティの予測が不要（伸縮性）
  • 「新しい国・地域ですぐにサービスを開始したい」→ 数分で世界中に展開できる

1つのリージョンには、原則として3つ以上の AZ があります。各 AZ は物理的に離れた場所にあり、電源やネットワークも独立していますが、AZ 間は低遅延の専用回線で接続されています。
単位概要押さえるべき点
リージョン
Region		AWS が拠点を置く地理的な地域（東京、大阪、バージニア北部など）リージョン同士は互いに独立している。データは利用者が明示的に移動・複製しない限り、他のリージョンへ移動しない。
アベイラビリティーゾーン（AZ）
Availability Zone		リージョン内にある、1つ以上のデータセンターから成る独立した区画複数の AZ にシステムを分散配置（マルチ AZ 構成）すると、1つの AZ に障害が起きても稼働を継続できる。これにより高可用性を実現する。
エッジロケーション

リージョン選択の4つの基準

🔑覚え方：「置ける？ 近い？ 使える？ 安い？」の順に問う
  1. 置ける？＝法令・規制への準拠（コンプライアンス）：データを国内に保管する義務がある場合、選べるリージョンは限定される。
    コンプライアンス：法令や業界規制、社内規程を遵守すること。
  2. 近い？＝地理的な近さ（レイテンシー）：利用者に近いリージョンほど応答が速い。
    レイテンシー：要求を送ってから応答が返るまでの遅延時間。
  3. 使える？＝サービスの提供状況：新しいサービスは一部のリージョンでのみ提供されている場合がある。
  4. 安い？＝価格：同じサービスでも、リージョンによって料金が異なる。

この4つに当てはまらないもの（AZ の数、サポートプラン）は基準ではありません。

⚠️間違えやすい点

リージョン選択の基準として適切でないものを選ばせる問題がよく出題されます。「AZ の数」や「サポートプランの種類」は、通常リージョン選択の基準には含まれません。上記の4つを正確に挙げられるようにしてください。

🎯試験での問われ方
  • 「1つのデータセンター（AZ）が止まってもサービスを続けたい」→ 複数の AZ に配置（単一障害点をなくし、可用性を上げる）
  • 複数の AZ で得られるのは可用性。「コストが下がる」「性能が上がる」は誤り
  • 「世界中の利用者に低遅延で」→ CloudFront のエッジロケーション、または複数のリージョンに配置
  • ELB はリージョンをまたいで振り分けられない（同じリージョンの AZ 間だけ）

5. AWS の操作方法

AWS マネジメントコンソールManagement Console
Web ブラウザから利用するGUI。画面操作でリソースを作成・管理する。
AWS CLICommand Line Interface
ターミナルからコマンドで操作するツール。スクリプト化により作業を自動化しやすい。
AWS SDKSoftware Development Kit
Python や Java などのプログラムから AWS を操作するためのライブラリ群。

いずれの方法も、内部では同じ AWS の API を呼び出しています。

サインインに使う認証情報は入口で違います。コンソールはユーザー名とパスワード（＋MFA）、CLI や SDK のようなプログラムからのアクセスはアクセスキー ID とシークレットアクセスキーの組です（第2章の IAM で発行します）。

🎯試験での問われ方
  • 「プログラムによるアクセスに必要な認証情報は（2つ選ぶ）」→ アクセスキー ID と シークレットアクセスキー
  • ユーザー ID・パスワードはコンソール用。「プライマリキー」はデータベースの用語で無関係
