1. クラウドとは？

会社が仕事でコンピューターを使うとき、昔は自分でサーバー（仕事用の強いコンピューター）を買って、自分の建物に置いていました。これをオンプレミスといいます。

それに対してクラウドは、インターネットの向こうにある AWS のコンピューターを、使いたいときに、使った分だけ借りるやり方です。

🏠たとえ話：自家発電と電力会社

オンプレミスは自宅に発電機を買って置くようなもの。最初にお金がかかり、こわれたら自分で直し、使わなくても置き場所をとります。

クラウドは電力会社から電気を買うようなもの。コンセントにさせばすぐ使えて、使った分だけ払えばいい。発電所の管理は電力会社（AWS）がやってくれます。

2. クラウドの6つのメリット

AWS は公式に「クラウドの6つのメリット」をあげています。試験にそのまま出るので、6つ言えるようにしましょう。

#メリット（公式の言い方）かんたんに言うと
1固定費を変動費にできる最初にドカンと買わず、使った分だけ払う。
固定費＝使っても使わなくても毎月かかるお金。変動費＝使った量で変わるお金。
2規模の経済の恩恵を受けられるAWS は何百万人分をまとめ買いしているので、1人あたりが安くなる。
規模の経済＝たくさん作る・買うほど1個あたりが安くなること。
3キャパシティの予測が不要「何台いるか」を前もって当てなくていい。足りなければ増やし、余れば減らす。
キャパシティ＝どれだけの量をさばけるか、という能力・容量。
4速度と俊敏性の向上サーバーが数分で手に入るので、新しいことをすぐ試せる。
俊敏性（しゅんびんせい）＝すばやく動けること。英語でアジリティ。
5データセンターの運用・保守への投資が不要建物・電気・冷房・故障対応は AWS まかせ。自分は本業に集中できる。
6数分で世界中に展開ボタン一つで、アメリカやヨーロッパにもサーバーを置ける。
🔑覚え方：「へん・き・よ・はや・ほ・せかい」

変動費 ／ 規模の経済 ／ 予測不要 ／ 速さ ／ 保守不要 ／ 世界展開

イメージ：「へんな き（木）に よるはやく ほしが せかいじゅう」—— 変な木に、夜はやく、星が世界中に光る場面を思いうかべる。

🎯試験に出るポイント
  • 「初期投資を減らしたい」「使った分だけ払いたい」→ 固定費を変動費に
  • 「需要がわからない」「アクセスの増減がはげしい」→ キャパシティの予測が不要（＝伸縮性）
  • 「新しい国でもすぐサービスを始めたい」→ 数分で世界中に展開

3. サービスの種類と使い方の形

IaaS・PaaS・SaaS —— どこまで自分でやる？

クラウドのサービスは、「AWS がどこまで面倒をみてくれるか」で3つに分けられます。

🍕たとえ話：ピザで考える
  • IaaS（イアース）＝ キッチンを借りる。オーブンはあるけど、生地も具も焼くのも自分。
  • PaaS（パース）＝ ピザの宅配。焼くところまでお店がやる。自分はどのピザにするか（＝自分のプログラム）を決めるだけ。
  • SaaS（サース）＝ レストランで食べる。全部お店。自分は食べる（使う）だけ。
種類意味AWS の例自分の担当
IaaSInfrastructure as a Service
インフラ（土台の機械）をサービスとして借りる		EC2OS・ソフト・データなど、多い
PaaSPlatform as a Service
アプリを動かす土台ごと借りる		Elastic Beanstalk自分のプログラムとデータ
SaaSSoftware as a Service
完成したソフトを使うだけ		WorkMail など
（身近な例：Gmail）		使い方と入れるデータだけ

クラウドの使い方の形（デプロイモデル）

デプロイモデルとは、「システムをどこに置くか」の分け方です。

形説明
クラウド
（クラウドネイティブ）		全部クラウドに置く。
ハイブリッドオンプレミスとクラウドをつないで両方使う。「古いシステムは社内に残しつつ、新しいものはクラウドで」など。
オンプレミス
（プライベートクラウド）		全部自社に置く。クラウドと同じような技術を社内で使うこともある。

4. AWS は世界のどこにある？（グローバルインフラ）

AWS のコンピューターは世界中のデータセンターに置かれています。その置き方には決まった「単位」があり、ここは試験で毎回のように出ます。

🏙️たとえ話：チェーン店のお店づくり
  • リージョン＝「東京エリア」「大阪エリア」のような地域。
  • アベイラビリティーゾーン（AZ）＝ その地域の中にある、はなれた場所にある別々の店舗。1つの店が停電しても、ほかの店で営業を続けられる。
  • エッジロケーション＝ 街中の小さな受け取り窓口。よく売れる商品だけ置いておき、お客さんに近いところですぐ渡す。

リージョン
Region		世界の「地域」。東京・大阪・バージニア北部などリージョン同士は独立。データは自分で動かさないかぎり、勝手にほかのリージョンへ移らない。

リージョンの選び方 —— 4つの基準

🔑覚え方：「ほう・ち・サ・か」（法・地・サ・価）
  1. 法律・ルール（コンプライアンス）：「データは日本国内に置くこと」という決まりがあれば、日本のリージョンしか選べない。
    コンプライアンス＝法律や決まりを守ること。
  2. 地理的な近さ（レイテンシー）：お客さんに近いほど速い。
    レイテンシー＝データが届くまでの待ち時間。小さいほど速い。
  3. サービスがあるか：新しいサービスは、まだ一部のリージョンにしかないことがある。
  4. 価格：リージョンによって料金がちがう。
⚠️ひっかけ注意

「どのリージョンを選ぶか」に関係ないものを選ぶ問題がよく出ます。たとえば「AZ の数」や「サポートプランの種類」は、ふつうリージョン選びの基準ではありません。上の4つを確実に言えるようにしましょう。

5. AWS をさわる3つの方法

マネジメントコンソールManagement Console
ブラウザで開く画面。マウスでクリックして操作。はじめての人向け。
AWS CLIコマンドライン インターフェース
黒い画面に文字の命令（コマンド）を打って操作。くり返し作業を自動にしやすい。
SDKソフトウェア開発キット
Python や Java などのプログラムの中から AWS を操作するための部品セット。

どの方法でも、裏では同じ API を呼び出しています。

オンプレミスとクラウドのちがいを、たとえ話で説明すると？
オンプレミスは自宅に発電機を置く（買う・置く・直すを全部自分で）。クラウドは電力会社から電気を買う（使った分だけ払い、管理は AWS）。
クラウドの6つのメリットは？
①固定費を変動費に ②規模の経済 ③キャパシティ予測が不要 ④速度と俊敏性 ⑤データセンター運用への投資が不要 ⑥数分で世界展開（へん・き・よ・はや・ほ・せかい）
IaaS・PaaS・SaaS をピザでたとえると？ AWS の例は？
IaaS＝キッチンを借りる（EC2）、PaaS＝宅配ピザ（Elastic Beanstalk）、SaaS＝レストランで食べる。
リージョン・AZ・エッジロケーションの関係は？
リージョン（地域）の中に複数の AZ（はなれたデータセンター群）がある。エッジロケーションは利用者の近くの小さな拠点で、CloudFront や Route 53 が使う。
システムを止まりにくくするには、AZ をどう使う？
複数の AZ に分けて置く（マルチAZ）。1つの AZ に障害が起きても、ほかの AZ で動き続ける＝高可用性。
リージョンを選ぶ4つの基準は？
法律・ルール（コンプライアンス）／お客さんへの近さ（レイテンシー）／使いたいサービスがあるか／価格（ほう・ち・サ・か）。
